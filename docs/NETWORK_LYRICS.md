# 网络歌词匹配

默认开启。在设置 → 歌词设置 → 歌词显示中关闭“网络歌词匹配”，Core 会取消尚未完成的网络请求。关闭值保存在 Core 的 `core-settings.json`，重启后保留。

## 归属和查询顺序

- Core 的 `CoreLyricsSource` 组合本地／服务器歌词与 `Echo.Lyrics` 模块；Control 仍使用已有的类型化歌词资源契约，不直接联网或访问曲库数据库。
- 显式导入、本地伴随文件和服务器歌词优先；只有缺失时才查询网络。已有歌词文件、标签和曲库行不会被改写。
- 网络元数据来自 Core 当前播放事实或单曲索引查询。缺少歌名、歌手或有效时长时不盲目匹配。请求不包含本地路径、凭据、封面或播放历史。
- 参考用户自有 Electron 仓库 `workshop/network-lyrics/authoring` 与 `src/main/lyrics`，将 AMLL、网易云、QQ 音乐和 LRCLIB 的查询／取词链路改写为 C#。不依赖 Electron、Node 或动态插件宿主。

## 匹配与格式

对歌名做 NFKC、大小写、标点和已知版本／合作歌手后缀归一化；识别歌手联合署名。候选必须同时满足歌名、歌手、版本与时长条件。现场、混音、伴奏、短版、不插电和翻唱版本不跨版本自动接受。相同来源最多尝试三个查询变体、取两个可信候选，错误候选不触发取词。

AMLL 使用详情的元数据重新校验，时长只认 TTML `body dur` 或独立网易云目录中的关联歌曲时长，不将最后一个唱词时间或查询自身时长当成证据。逐字 TTML 优先，其次比较逐字、逐行和纯文本质量；网易云 YRC、QQ QRC、译文和罗马音交给现有歌词解析器。

这是内置自动匹配路径；Electron 版的手动候选选择、跨来源歌词正文共识与复杂别名词典没有随本次迁移。

## 资源与故障

- Core 全局串行匹配，最多八个等待请求；一次最多四个来源并行，不广播整库或逐帧查询。
- 总查询预算八秒，单次 HTTP 四秒；响应最多 2 MiB，JSON 深度最多 32。HTTP 客户端归 Core 所有，不使用 Cookie 或自动重定向。
- 成功歌词缓存最多十六项、约 2 MiB UTF-16 文本，十分钟过期；没有歌词和服务错误均不缓存。
- 某个来源错误、超时或超大响应不丢弃其他来源已完成的结果；用户取消则丢弃整个请求。所有来源失败通过歌词专用错误回传，界面允许重新加载或导入。
- 歌词资源使用独立的有界读取槽，不占用封面／附件读取槽。关闭 Core 时取消请求并释放网络与本地读取资源。

## 验证入口

`dotnet run --project tests/Echo.NetworkLyrics.Smoke`

覆盖四源解析、错误歌曲／版本拒绝、逐字和翻译、独立时长证据、缓存复用、HTTP 取消、慢详情保留已完成 TTML、超大响应回退、关闭时取消、默认开启与设置持久化，以及实际本地 IPC 下多 Control 共享设置、歌词读取、断开和释放。音频使用空闲替身，不代表设备播放验收。

可选实网检查：`dotnet run --project tests/Echo.NetworkLyrics.Smoke -- --live`。本次《晴天》匹配返回 AMLL TTML，62 行、492 个逐字片段，约 4.2 秒；仅代表当次网络和服务状态。
