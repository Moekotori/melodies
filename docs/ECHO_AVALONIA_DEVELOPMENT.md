# ECHO Avalonia 开发文档

更新日期：2026-10-02  
目标平台：Windows、macOS、Linux  
开发位置：当前新工作区  
状态：架构与开发约束已确定；扫描及独立数据库已有实现和短测，完整应用目标与平台验收仍按各模块推进

本次重写采用 Avalonia、C# 与现有 C++ 音频底层。开发从第一阶段就执行性能预算、资源所有权、调度隔离和动画生命周期规则。文件按职责组织，每次迁移交付一个可运行的能力，保留明确的回滚入口。

本文同时是开发路线和代码评审依据。“必须”表示实现约束；表中的性能数值是首版设计目标，需要通过 Release 原型校准，不能当作已经达到的性能。旧 ECHO 中暂停 Avalonia 的历史准备记录已被本次选择更新；开发在新工作区分阶段推进，保留旧项目与生产数据的迁移边界。已实现扫描能力见 [扫描和数据库模块](SCANNING_DATABASE.md)，实测见 [扫描性能短测](SCANNING_PERFORMANCE.md)。

## 技术选择

| 层次 | 选择 | 使用方式 |
| --- | --- | --- |
| 桌面界面 | Avalonia 稳定版 | 起步时核对已发布稳定版本，锁定包版本；界面默认启用编译绑定 |
| 托管运行时 | .NET 10 LTS | 与现有 Echo.Core 目标框架一致，集中管理 SDK 和依赖版本 |
| 界面状态 | 轻量 MVVM，优先 CommunityToolkit.Mvvm 源生成器 | 不引入全局状态大仓库，不为简单交互默认叠加响应式框架 |
| 曲库 | 复用适用的 Echo.Core 与 SQLite | 先保留已工作的查询和命令，再迁移剩余业务及 schema 所有权 |
| 音频数据面 | 现有 C++20 Native Audio Host | 保留解码、PCM、DSP、输出设备和权威时钟 |
| 音频控制面 | C# 播放会话模块 | 迁移 AudioSession 中必要的编排、命令序列、队列推进和恢复 |
| 后台执行 | 有界 Channel、固定工作器、统一资源准入 | 限制排队数量、字节数、并发、预估峰值内存和磁盘竞争 |
| 序列化 | System.Text.Json 源生成 | 类型化小消息；控制消息与大资源读取分开 |
| 发布 | 从开始保持 Native AOT 兼容，同时保留普通 Release 对照 | 实际依赖、系统集成和诊断通过验证后确定各平台最终发布方式 |
| 原生集成 | 平台适配模块 | Win32、macOS 和 Linux 差异集中装配，不进入业务和页面 |

SDK 用 global.json 锁定，NuGet 版本用 Directory.Packages.props 集中管理；不使用浮动版本。MVVM 工具包只用于必要的属性和命令生成，不成为业务依赖。[.NET 支持策略](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)、[MVVM Toolkit](https://learn.microsoft.com/en-us/dotnet/communitytoolkit/mvvm/)。

Avalonia 的编译绑定、虚拟化和线程模型作为实现基础，具体版本行为以锁定版本为准。[编译绑定](https://docs.avaloniaui.net/docs/data-binding/compiled-bindings)、[性能指导](https://docs.avaloniaui.net/troubleshooting/app-performance-issues)、[线程模型](https://docs.avaloniaui.net/docs/app-development/threading)。

Native AOT 需要处理反射、动态代码与依赖裁剪，不等于消除 GC。Debug 保持正常开发体验，Release 原型从早期检查 AOT 兼容；某项插件不兼容时单独隔离，不通过关闭整个项目的兼容检查掩盖问题。[Avalonia Native AOT](https://docs.avaloniaui.net/docs/deployment/native-aot)、[.NET Native AOT](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)。

基础界面不装配浏览器引擎。HTML 主题和 Node 插件兼容属于独立迁移能力，见后文的兼容边界。

## 架构和唯一所有者

按 2026-10-19 的桥核分离决定，默认运行形态为 Avalonia Control 客户端、独立 C# Core 服务及按播放需要启动的原生音频宿主；启用连接服务时再按需启动独立 Bridge。Core 仍以模块化单体组织业务，不按每个模块增加进程。Control 断开不结束已经接受的任务或播放，同库多客户端共享一个 Core owner。接口、预算、入口和当前网络输出边界见[桥核分离](BRIDGE_CORE_SEPARATION.md)；独立设备端可按[网络 Output V1](NETWORK_OUTPUT.md)显式绑定，音频处理仍留在原生进程。统计与验证包含上述完整进程树，旧单托管进程预算需按新拓扑重新测量，不沿用为已达成的数字。

```text
Echo.Desktop
  页面、控件、当前视图状态、动画生命周期
          |
Echo.Application
  播放会话、队列、扫描编排、任务调度与资源策略
          |
Echo.Contracts
  ID、分页 DTO、命令结果、能力、时钟与模块接口
          |
Echo.Infrastructure
  原生传输、数据库调度、文件访问、封面、平台适配
          |
          +-- Echo.Core：既有曲库业务与可复用纯算法
          +-- SQLite：曲库事实、队列顺序和持久化记录
          +-- C++ Native Audio Host：音频数据面和权威事实
```

上图表示调用边界；项目依赖必须遵循下一节的单向规则。

| 事实或资源 | 唯一所有者 | UI 可以持有什么 |
| --- | --- | --- |
| 曲目、收藏、歌单、队列顺序 | 曲库持久化服务与 SQLite | 当前页 DTO、稳定 ID 和必要的选择状态 |
| 活跃播放会话与命令顺序 | PlaybackSessionCoordinator | 只读会话快照和用户命令入口 |
| 解码、PCM、DSP、设备、EOF、drain | Native Audio Host | 状态、诊断摘要和小型可视化数据 |
| 播放位置 | 原生时钟；应用层发布有版本快照 | 用于画面的短时插值，不能据此推进队列 |
| 图片字节和解码对象 | 有预算的 ArtworkService | 带生命周期的图片租约 |
| 页面动画与绘制资源 | 对应窗口或可见视图 | 可取消动画、局部绘制状态 |
| 后台任务准入 | WorkScheduler 与 MemoryPressureCoordinator | 真实任务状态，不创建第二套任务队列 |
| schema 版本与迁移 | SchemaMigrator | 只读初始化状态 |

UI 不访问数据库连接，不打开音频设备，不修改会话事实。控件上的“播放中”以确认后的实际状态为准；等待状态对应真实任务及原因。

编译依赖遵循这些规则：

- Contracts 不引用 Avalonia、Electron、数据库实现或平台 SDK。
- Core 引用必要契约和已有存储依赖，不引用 Desktop 或 Application。
- Application 引用 Contracts，通过端口编排能力，不引用具体基础设施。
- Infrastructure 实现端口，可引用 Contracts 和 Core，不引用 Desktop。
- Desktop 的功能代码只调用 Application 和 Contracts。Bootstrap 可以引用 Infrastructure 和 Core，集中装配依赖。
- 平台判断只出现在 Infrastructure/Platform 和 Bootstrap。业务读取能力表，不散落系统判断。
- 依赖从装配入口注入，禁止全局服务定位器和模块之间的可变静态共享状态。

小功能可以在现有模块中按文件拆分。只有独立依赖、生命周期或测试边界值得隔离时才建立新项目，避免每个类一个程序集。

### 文件规则

一个文件负责一类工作。ViewModel 管局部展示状态和命令入口；Service 管业务；Repository 或 Core 查询模块管数据；Adapter 管外部边界；Coordinator 管组合与状态转换。

普通手写 C# 文件目标不超过 350 行；超过 500 行必须说明无法安全拆分的原因或按职责拆出模块。页面 XAML 目标不超过 250 行，行模板、设置分组和复用控件独立维护。这些阈值是评审提醒，不能靠压缩代码、机械切片或提高阈值规避。生成代码、SQL 迁移和资源文件单独计量。

App、主窗口和 Bootstrap 保持薄。禁止把数据库、播放会话、所有设置、所有事件监听继续堆进 MainWindowViewModel 或 App.axaml.cs。

接口只为真实替换边界建立，例如音频、曲库、平台和资源读取。不为单个内部类机械增加同名接口，不增加只转发一次调用的多层包装。

每个模块随实现维护一张简短说明：职责、输入输出、依赖、资源所有者、内存上限、取消方式、释放时机和迁移完成状态。重要契约随代码记录，不要求重复写一套长文档。

## 首版性能目标与测量口径

参考场景暂定为 4 核以上 CPU、8 GiB 内存、SSD、1920×1080、100% 缩放、60 Hz、Release 发布产物。使用固定 5 万曲目曲库和同一组本地文件；CPU 型号、OS、渲染后端、发布方式及显示缩放必须写进测量记录。另设 HDD 和高 DPI 场景，不把 SSD 缓存结果外推。

| 项目 | 首版目标 | 测量边界 |
| --- | --- | --- |
| 已建立曲库的冷启动首个可交互窗口 | 2 秒内 | 从进程启动到按钮可响应；不包含安装、首次导入和必需的首次迁移 |
| 热启动首个可交互窗口 | 1 秒内 | 单列缓存状态，不能与冷启动混用 |
| 常规按钮与导航反馈 | 100 ms 内 | 从输入到可见反馈；设备完成时延单列 |
| 索引已建立的搜索首屏 | p95 不超过 150 ms | 从提交查询到显示有效第一页；输入防抖另列 |
| 索引支持的列表翻页 | p95 不超过 100 ms | 读取 200 行，禁止附带封面解码和整库计数 |
| UI 线程工作 | p95 每帧不超过 4 ms | 布局、绑定和提交；不能用它代替完整呈现帧时 |
| 标准动画 | 目标 60 fps，呈现间隔目标 16.7 ms | 单列晚帧、长帧和渲染后端；高刷新模式另测 |
| Windows 常规播放进程组 private bytes | 目标不超过 180 MiB | 托管进程加原生 Host 及其他已启动辅助进程；普通立体声 PCM、单窗口、无插件 |
| Windows 扫描并播放峰值 private bytes | 目标不超过 256 MiB | 同一测量口径；同时记录采样间隔与短峰值遗漏 |
| 隐藏主窗后的视觉工作 | 停止主窗连续绘制 | 可见桌面歌词或迷你窗口单独计量 |
| 无扫描、无动画的静态播放 CPU | 平均不超过一个逻辑核的 2% | 排除高负载 DSP；说明归一化方式，不能混用系统百分比 |
| Native Audio 回调 | 不新增分配、阻塞和托管调用 | 设备相关 underrun、xrun 与最大回调耗时必须单列 |

数值用于约束第一版设计。原型未达到时先归因，记录成本属于运行时、查询、图片、原生 Host 还是功能；调整目标需要具体测量和取舍说明，不能把当前占用直接改成新预算。

Windows private bytes、Linux PSS/RSS、macOS footprint 是不同指标。Linux 优先采集进程组 PSS，同时记录 RSS；macOS 记录各进程 footprint 与内存压力。不要把跨平台不同指标硬比同一个 180 MiB 数值，也不要把共享 RSS 简单相加当成独占占用。显存、图形资源和托管堆单独记录。

首版目标聚焦普通使用路径。高倍率 SRC/SDM、多声道、超大封面、插件和多个窗口分别建立场景预算；启用额外能力时报告增量成本，不能让常规路径默认承担它们。

## 启动与交互速度

启动按关键依赖分阶段：最小服务与窗口、必要数据库版本检查、第一页查询、按需音频初始化。旧库必须升级才能安全读取时，显示明确的初始化进度；不能绕过迁移强行展示旧 schema。

托盘、远程连接、插件、波形、网络元数据和全库统计按需启动。首次显示不等待全库扫描、罗马音构建、全部设置页创建或封面预热。

启动、搜索、导航统一采用请求 generation。新操作取消未开始的旧工作，已完成的旧结果在提交 UI 前再次比对版本。页面退出后，迟到结果不能重新建立图片或订阅。

搜索默认防抖 120 ms，回车立即提交；只保留最新待处理搜索。界面先显示现有可用结果或加载状态，不清空后连续闪烁。分页查询只返回必要列，昂贵统计独立缓存或后台计算。

不在 UI 线程执行磁盘 I/O、同步数据库、图片解码、歌词全文解析、原生进程启动或同步等待。禁止用 .Result、.Wait() 或连续 Dispatcher.Post 掩盖阻塞。异步完成后只把小型结果批次交回 UI。[Avalonia 线程模型](https://docs.avaloniaui.net/docs/app-development/threading)。

## 曲库与列表

控件虚拟化只限制实例数量；数据源本身也必须分页。禁止先创建 5 万个 ViewModel，再交给虚拟列表。

初始页大小 200 行；数据驻留默认不超过 3 页即 600 行，播放队列展示窗口最多 1000 行。预取仅覆盖相邻页，页面退出取消预取。ID 选择、队列真实顺序和跨页批量操作通过数据库或有界批次完成；“全选”用查询条件和版本表达，不能拉整库 ID 到 UI。

优先复用锁定版本中经过验证的虚拟容器和轻量行模板。ScrollViewer 与面板结构必须给虚拟化容器有限视口，避免嵌套滚动和无限测量导致所有行被实例化。查看实际 realized 行数，不只检查是否写了 VirtualizingStackPanel。[Avalonia 性能指导](https://docs.avaloniaui.net/troubleshooting/app-performance-issues)。

过滤、排序、分组和统计由 Core/SQLite 执行。深页导航优先考虑稳定游标和已有有界排序索引；保留需要的随机跳转能力，避免对超深 OFFSET 无条件全表扫描。

播放 tick 不更新整张列表。当前曲目 ID 变化只影响旧行和新行，音量或进度变化只更新对应控件。封面就绪仅通知可见行。批量更新应保持选择、滚动位置和最小通知范围，不能通过反复重置 ItemsSource 达成。

## 数据库和写入调度

目标版本中，同一曲库只有一个应用级写入协调者。所有用户写入、扫描写入、索引维护和 schema 迁移都走明确的所有权协议；不能让新 UI、旧 Electron 和 Core Host 同时自主写同一个生产库。

Microsoft.Data.Sqlite 的异步 ADO.NET 方法仍会同步执行数据库工作。因此数据库操作必须进入数据库执行器，不能以 ExecuteReaderAsync 的名称判断它不会阻塞 UI。[Microsoft.Data.Sqlite 异步限制](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/async)。

初始采用一个写入工作器和最多两个读取工作器，连接与执行上下文绑定，不跨线程同时使用连接。把交互读取、用户写入和后台批次区分排队；后台任务不得把两个读工作器都长期占满。WAL、连接缓存和超时属于显式配置，必须考虑总内存及文件系统兼容性。

用户写入优先于下一批扫描写入；已开始的事务不被强行中断。扫描初始每批 200 条，单批占用目标不超过 50 ms，随设备测量缩小批次。批次大小可调不能把业务要求的原子操作机械拆开。超过时限的事务需要拆出准备工作或修正 SQL，不无限重试锁争用。

取消具有三个层次：排队取消、批次间取消、底层正在执行的操作取消。实现必须说明实际支持到哪一层；Token 取消和忽略旧结果不能宣称已经终止 SQLite 或原生解码工作。

改变状态的请求包含稳定 operationId、会话或数据库 generation、明确结果。提交记录与数据库修改同事务持久化。超时且结果不明时查询原提交记录，不生成新 ID 自动重写，不切换旧后端重放。提交已完成但结果显示失败时提供刷新与恢复。

维护任务不得长事务占用交互通道。VACUUM、全库重索引和迁移放在明确维护阶段，显示真实状态并允许安全取消或恢复。

## 后台调度与资源准入

### 优先级与执行边界

音频实时回调独立运行在 Native Host 中，不经过通用调度器。下表 P0 是播放控制优先级，不代表 C# 工作器成为实时线程。

| 等级 | 工作 | 调度要求 |
| --- | --- | --- |
| P0 播放控制 | pause、stop、seek、会话关闭、EOF 处理 | 独立命令通道；后台工作不占其排队容量 |
| P1 用户交互 | 当前页查询、显式导入、可见封面、用户写入 | 预留读写执行机会和资源容量 |
| P2 临近需求 | 下一页、下一曲必要元数据与解码准备 | 可取消、有限预取，不抢 P1 |
| P3 后台 | 扫描、补索引、封面生成、网络补全 | 分批、可暂停；受播放、磁盘和内存压力约束 |

PlaybackCommandLane 初始有界容量 32。只合并尚未执行的连续 seek 或音量变更，保留最后目标及序号；play、stop、队列推进和已发出的状态改变不能任意丢弃。stop/关闭保留独立待处理信号，即使普通命令队列满也能进入安全终止流程。已经进入原生执行的命令按契约确认，不假装能够随时抢占。

通用任务队列总量初始不超过 128，排队描述及载荷总预算 8 MiB。队列满时交互返回可说明的繁忙状态，后台异步等待或持久化进度后延迟，不在调用方继续堆任务。调用方数量同样有上限，否则等待的 WriteAsync 本身仍会积累。

有界 Channel 提供排队上限和背压；任务数量限制之外仍需字节预算、资源租约和固定生产者数量。[.NET Channels](https://learn.microsoft.com/en-us/dotnet/core/extensions/channels)。

### 初始并发和公平性

| 工作 | 初始并发 | 约束 |
| --- | --- | --- |
| 播放控制 | 1 个串行 owner | 按会话及命令版本确认 |
| 交互数据库读取 | 最多 2 | 至少保留一个读取机会给 P1 |
| 数据库写入 | 1 | 用户写入先于下一后台批次 |
| 封面解码 | 1，设备允许时最多 2 | 受像素、字节和可见性预算共同限制 |
| 扫描 metadata | 默认 2，SSD 空闲时最多 4 | HDD 或播放压力时降为 1；不按 CPU 核数无上限扩张 |
| 非必要网络补全 | 最多 2 | 超时、取消、去重；不属于启动关键路径 |
| CPU 重分析 | 默认 0，显式请求后最多 1 | 不与音频热路径争抢；需资源准入 |

这是初始配置，不保证其已是最优值。扫描吞吐目标由目录发现、metadata、数据库提交、封面及索引阶段分别测量，不能只把文件发现速率当成导入完成速率。

P1 有独立预留，不仅在一个全局队列中排序。P3 每批结束都检查取消、交互负载和压力；正常压力且交互负载低时给等待较久的后台批次有限执行机会，避免永久饥饿。压力恢复后的积压逐批放行，禁止同时启动所有工作器。

不得使用每文件一个 Task.Run、每图片一个无限等待任务或无界 Parallel.ForEachAsync。固定工作器消费有界批次，资源租约在 finally 中释放。

### 任务描述和背压链路

每项可调度任务至少包含：owner、类型、优先级、去重键、generation、预计 CPU/磁盘成本、峰值内存预留、截止时间、取消方式和完成状态。

流式扫描链路为目录发现、metadata、提交与后处理。每一段都有有界队列；下一段满时上游停止继续生产。进度只保留计数、有限错误样本和持久化游标，不保留整批扫描对象树或完整路径历史。

资源预留表示可控生产者预算，不等于操作系统的物理内存保证。实际峰值高于估计时记录偏差、缩小后续任务并触发压力策略。固定音频缓冲在播放前分配并计入预算，后台 admission 不能拒绝已有播放所需的稳定工作。

页面隐藏、用户手动暂停和内存压力是独立的暂停原因。移除某个原因不能清空其他原因；状态展示明确说明任务究竟正在运行、等待、暂停还是完成。

## 内存预算与释放

### 初始资源上限

下面是常规模式的初始资源预算，属于整体进程占用中的部分组成，不是互不重叠的完整账目。原始字节、解码对象与 GPU 副本必须分别统计。

| 资源 | 初始上限 | 所有者及释放 |
| --- | --- | --- |
| 列表缩略图解码缓存 | 32 MiB | ImageLeaseCache；按实际像素字节 LRU，淘汰仅无活跃租约项 |
| 当前封面与切换中封面 | 16 MiB | 当前播放器视图；默认按显示像素解码，普通模式单张最多 1024×1024 |
| 文本布局与 glyph 相关应用缓存 | 4 MiB | 歌词可见区域；字体、缩放或曲目变化时失效 |
| UI 曲库 DTO 与队列展示 | 8 MiB | 分页源；离页释放，不含数据库事实 |
| 待处理图片请求 | 最多 64 个，载荷 4 MiB | ArtworkService；相同目标合并，旧 generation 丢弃 |
| 可视化快照 | 1 MiB | 仅最新有界帧，读写缓冲复用 |
| 应用可控 GPU 图片资源 | 初始目标 64 MiB | 图形资源 owner；后端不可观测部分单列 |
| 调度排队载荷 | 8 MiB | WorkScheduler；完成、取消、过期均释放 |
| 内存日志 | 4 MiB | 有界环形缓冲；重复事件聚合 |
| 本地诊断文件 | 3 个，每个最多 8 MiB | 滚动写入，按用户操作导出 |

队列项数、字节数和对象引用都要受限，不能靠压缩字符串后保留完整对象绕开预算。数据库连接缓存、原生音频内存、渲染表面、运行时、插件及临时解码峰值额外计入完整进程组。

封面先取得尺寸并检查像素与峰值预算，避免直接解码原始超大图片。解码目标包含实际显示尺寸与 DPI，缩略图与大封面不能互相误用。全尺寸资源只在显式查看时请求，关闭查看器后释放。

共享图片使用租约或引用计数，控件解除 Image.Source 后释放自己的租约；缓存不能处置仍被其他视图使用的对象。图形对象的处置线程按锁定后端要求执行。取消后的迟到结果没有合法 owner 时立即释放。

页面默认只保留当前视图及一个过渡中的旧视图。导航历史保存轻量状态、查询条件和滚动位置，不保存完整视觉树。窗口关闭、视图脱离、取消和服务退出都必须解除订阅、定时器、动画、CTS 和资源租约。

### GC 与分配

桌面进程先用 Workstation GC 和常规交互模式；不默认启用 Server GC、长期 NoGCRegion 或全局 SustainedLowLatency 来掩盖分配。原生音频回调不调用托管代码，因此不依赖冻结整个应用 GC 保持音频输出。

SustainedLowLatency 可能扩大堆和碎片，应只在有测量依据的有限场景评估。禁止周期性 GC.Collect 和设置页“清内存”作为主要治理方式。[.NET GC 延迟模式](https://learn.microsoft.com/en-us/dotnet/standard/garbage-collection/latency)。

热点避免每帧 LINQ、闭包、字符串格式化和新数组。可视化缓冲复用；使用池化时限定池和最大租用长度，不能为了省分配无限保留大数组。native、托管、图片与 GPU 资源分别记账，托管堆下降不能单独证明应用内存下降。

### 压力分级与恢复

| 等级 | 行为 |
| --- | --- |
| L0 正常 | 按既定资源预算运行 |
| L1 轻度 | 暂停新后台重任务，缩小预取，释放无租约缓存，降低装饰效果 |
| L2 严重 | 停止非关键生产，取消未开始的大图片/分析，保留播放和必要操作 |
| L3 持续保护 | 只保留播放、安全控制和轻量恢复交互；继续监测基础压力以便退出 |

Windows 首版可用 220 MiB 作为 L1 调查线、320 MiB 作为 L2 调查线，同时参考系统可用内存、增长速率与图形故障。它们是保护候选值，不能代替前面的常规目标，也不能直接套到 macOS 或 Linux 的不同指标。首个 Release 基线后确定最终阈值。

采样初始每 2 秒一次，详细进程采样按平台成本降低频率。采样缺失记为 unknown，不能当成 0，也不能因遥测失败停止播放。

基础压力等级与持续保护状态分开计算，避免 L3 反过来阻止自身恢复。恢复使用低于进入线的阈值、连续稳定样本和最小驻留时间：初始 L1 至少 15 秒，L2 恢复需要 6 个稳定样本，L3 恢复需要 15 个稳定样本。参数需随采样周期一起配置，恢复后缓慢放行生产。

清理按 owner、成本、超时和最小间隔执行，不在 UI 上同时处置大量对象。清理失败不能阻塞其他清理，未发现收益时记录原因，不循环强制 GC。

## 动画与歌词渲染

### 动画实现

简单属性反馈使用 Transition；持续位移、透明度或组合动画优先评估 Avalonia Composition。Composition 可以承担渲染线程动画，但不代表绑定、文本排版、布局和应用代码自动脱离 UI 线程。[Avalonia 动画](https://docs.avaloniaui.net/docs/graphics-animation/animations)。

优先改变 RenderTransform、Opacity 和局部绘制参数。避免逐帧改变整页 Width、Height、Margin 或触发整棵树布局。需要布局变化时一次计算目标布局，再播放有限过渡。

主题切换不能重建所有页面和图像缓存；颜色使用语义资源，资源更新范围和过渡按窗口预算处理。模糊、阴影、玻璃和离屏 Layer 按面积及生命周期预算装配，不默认给每一行或整窗动画附加昂贵效果。

| 场景 | 初始时长 | 约束 |
| --- | --- | --- |
| hover、按压、局部反馈 | 80 至 120 ms | 小范围明暗、缩放或透明度 |
| 展开与折叠 | 140 至 180 ms | 只更新必要子树 |
| 页面切换 | 180 至 220 ms | 最多保留两个视图；结束释放旧页面 |
| 播放封面切换 | 160 至 220 ms | 两张图片同时受封面预算限制 |
| 导航快速重复 | 跟随最新目标 | 不堆动画队列，不等待过期过渡结束 |

过渡结束或取消后必须到达有效的最终状态。透明页面切换时，旧页面完全退出绘制及命中测试，不能留下半透明旧设置页残影。快速反向切换从当前视觉状态继续，且保证资源生命周期收口。

### 帧率与可见性

| 模式 | 歌词连续插值上限 | 频谱和装饰上限 | 策略 |
| --- | --- | --- | --- |
| 轻量 | 关闭连续插值 | 频谱最多 15 fps，装饰关闭 | 按行/词时间边界及低频进度更新 |
| 均衡，默认 | 60 fps | 频谱 30 fps，装饰按需且最多 30 fps | 不因 144/240 Hz 屏幕自动扩大计算量 |
| 高流畅，显式开启 | min 屏幕刷新率与 120 fps | 频谱最多 60 fps | 帧预算或压力不足时回落 |
| 主窗隐藏或最小化 | 主窗停止 | 主窗停止 | 播放和必要系统事件继续 |
| 窗口失焦但仍可见 | 歌词默认最多 30 fps | 装饰暂停 | 用户显式高流畅需求另行评估 |
| 系统减少动画或用户关闭 | 关闭非必要连续过渡 | 装饰关闭 | 保留准确、可读的状态变化 |

这是应用产生更新的上限，不是显示器呈现保证。可见桌面歌词和迷你窗口有独立可见性与预算，不能因主窗口失焦就停掉仍在显示的歌词。

每个可见绘制场景最多一个帧驱动器，多个控件共享时间信息；停止状态、隐藏状态和无动画状态注销驱动。优先接入可验证的绘制节奏，不能启动一个永远运行的 1 ms 定时器追求高刷新。

### 歌词热点边界

歌词文件在后台解析，排版按曲目、字体、宽度和 DPI 缓存。界面只保留当前行附近的可见文本布局，超长歌词不为所有词永久创建控件。

逐字高亮采用局部绘制或缓存文字加裁剪，在当前行更新绘制进度；禁止每字一个动画、每帧重建字符串或向整张歌词列表广播 PropertyChanged。行切换才更新必要位置，词进度不触发全页面布局。

原生时钟快照包含单调时间锚点、播放速率和会话版本。视图仅在短窗口内插值，初始最大插值跨度 250 ms；超时、seek、pause、设备重启和会话变更后立即失效并等待新事实。UI 插值不能确认 EOF、drain、输出采样率或 bit-perfect。

频谱通过固定大小最新帧发布，只供可见消费者读取，不把 PCM 或完整波形送入 UI。实时回调不做 JSON 序列化、日志和阻塞传输；采样及发布在独立受限路径完成。无消费者时停止非必要频谱分析。

## 播放和平台集成

迁移普通本地立体声播放优先。保留有效的 WASAPI、ASIO、CoreAudio、PipeWire/ALSA 路径与能力回退语义，额外模式只在平台确实支持时显示。

状态改变型原生命令必须等待契约规定的确认。区分进程已启动、协议握手完成、设备已打开和实际播放状态；不能收到 process ready 就显示设备输出已就绪。

PlaybackSessionCoordinator、PlaybackCommandLane、PlaybackQueueService 和 NativeHostLifetime 分开维护。会话 owner 唯一，旧会话回调按 generation 拒绝，EOF/drain 引发一次队列推进。Host 退出后撤销订阅及 pending 请求，保留可解释的重试路径，重启不能自动重复不明操作。

音频后端优先复用现有受控进程接口。没有性能证据时，不为省一个 IPC 跳转把整个 C++ 引擎塞进托管进程，也不同时重写传输、解码、DSP 和 UI。

| 平台 | 音频方向 | 系统集成方向 | 完成依据 |
| --- | --- | --- | --- |
| Windows | WASAPI，能力允许时 ASIO | 系统媒体控制、托盘、快捷键、窗口行为 | 实机播放与设备事件，不只编译 |
| macOS | CoreAudio | 媒体控制、菜单、窗口生命周期和发布配置 | 实机、睡眠恢复和签名产物验证 |
| Linux | PipeWire/ALSA | MPRIS、托盘、桌面与窗口系统适配 | 目标发行版及实际会话验证 |

锁定 Avalonia 版本后核对 X11、Wayland、macOS 版本和各 CPU 架构支持范围。原生库、FFmpeg、Host 与应用按相同目标架构打包，构建产物不跨平台复用。[Avalonia 支持平台](https://docs.avaloniaui.net/docs/supported-platforms)。

## 简化迁移的契约

迁移围绕五个真实替换边界：曲库、播放、平台、图片和插件。接口使用 ID、小型 DTO、分页游标、取消与明确错误结果；不要传 Avalonia Bitmap、Electron WebContents、数据库连接或 DOM/CSS 对象。

图片契约使用资源标识和带租约的缩略图读取。旧 echo-cover:// 地址只留在旧界面适配中，不进入通用 Core 模型。

进程接口具有版本、能力握手、消息大小和 pending 请求上限。业务接口不必因进程边界而全部 JSON 化；同进程调用保持直接类型化调用。应用使用同一语义端口切换已验证实现，不能运行中把一个播放会话或不明写入换给另一个 owner。

复用旧模块时保留来源版本与最小迁入记录。先适配再收口，完成一个能力后移除该能力已无用途的重复实现；旧项目在整体验收前仍保留为回滚应用。共享代码必须成为明确的模块或版本化源码，禁止运行时引用开发者机器上的旧仓库绝对路径。

### 数据迁移和回滚

早期只读曲库用 SQLite Backup API 或验证过的一致性快照生成副本。WAL 模式不能只复制主 db 文件。连接和未完成写入关闭前不得随意拷贝、覆盖生产数据库。[SQLite 备份](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/backup)。

SchemaMigrator 是新应用唯一迁移入口，有 schema 版本、备份、事务和失败恢复。锁定规范化数据库标识与 generation，维护或迁移期间拒绝业务写入。

新旧应用使用独立应用数据目录。阶段二在副本上读；阶段四在副本上验证写入与一致性；正式切换在旧应用关闭并建立可恢复备份后进行，不能一边迁移一边让旧应用写生产库。

保留歌曲 ID、歌单 ID、顺序、收藏、播放历史、路径映射和用户配置的兼容语义。路径按平台规范化，不能把 Windows 盘符和大小写规则照搬到其他系统。

原数据库和兼容导出是回滚依据。新版本新增的不兼容 schema 不能直接交回旧程序打开；回滚恢复切换前备份，新版本期间的新增数据通过明确的兼容导出恢复。禁止用删除曲库、重新扫描或覆盖用户配置作为默认回滚方法。

### 插件与主题边界

既有 HTML/CSS/JS 主题和 Node 插件无法直接当成 Avalonia 控件加载。先建立兼容矩阵：原生声明式主题、受限命令插件、HTML UI、完整系统插件和 DSP 配置分别说明状态。

原生声明式主题优先迁移到语义 token 和受控组件。HTML/Node 兼容运行时若保留，必须独立、按需启动、可退出，并保留原有能力授权和隔离；其浏览器、Node 与辅助进程都计入启用该功能后的内存。

每项旧功能在迁移清单中标记保留、适配、延期或经用户决定退出。基础播放器完成不等于 ECHO 全部功能完成。Steam、Workshop、桌面歌词、备份、远程控制及专业音频能力都要有实际入口、错误状态和恢复方式。

## 分阶段开发与退出条件

每阶段交付一个可启动、可说明能力边界的版本。已通过的检查只在相关行为变化后重跑，不用全量验收拖慢每个阶段。

| 阶段 | 工作 | 退出条件 | 回滚点 |
| --- | --- | --- | --- |
| 零 事实与契约 | 盘点真实音频路径、Core API、schema、功能矩阵、资源和平台支持 | 每个待迁能力有 owner、入口、输入输出和未知项；取得最小基线或明确未测 | 无运行行为变化 |
| 一 最小桌面壳 | 建立必要项目、依赖方向、编译绑定、主题与局部动画、按需装配 | 壳可启动和退出，视图/资源释放可检查；建立短测口径 | 新工作区独立于旧版 |
| 二 只读曲库 | 复用 Core 查询，接副本数据库、分页与可见封面 | 5 万曲目列表与搜索可用，realized 行数及缓存受限；没有生产写入 | 删除新应用副本即可退出试用 |
| 三 真实播放 | 接实际 Native Host，迁移最小会话、命令、队列与基础歌词 | play/pause/seek/切歌/EOF/退出可用，旧会话事件不影响新会话 | 保留旧应用，不改原生热路径 |
| 四 写入与扫描 | schema owner、提交记录、歌单和扫描写入、背压与压力恢复 | 副本写入一致、取消有实际边界、扫描并播放可响应、不重放不明写入 | 保留副本和切换前备份 |
| 五 完整体验 | 逐字歌词、动画预算、多窗口、系统集成与对应平台适配 | 显示/隐藏/失焦/快速导航资源收口；对应平台完成真实验证 | 能按能力关闭新体验，保持基础播放 |
| 六 兼容与发行 | 插件、主题、Steam/Workshop、备份/远程等能力迁移；AOT 与打包 | 功能矩阵明确，已交付能力有完整路径；发布产物和三个目标系统分别验收 | 备份与兼容导出支持版本回退 |

首次开发只创建阶段一和下一项真实能力所需的结构。禁止一次性复制全部旧服务、生成所有空壳项目、把 TypeScript 巨型文件逐行翻成同名 C# 巨型文件。

一项迁移变更必须说明：迁移的入口、实现归属、接口变化、资源增量、取消与释放、最小验证、旧实现何时删除及回滚方式。没有明确边界时先拆出适配器和实际契约，不同时修改多条高风险链路。

## 诊断与短时间验证

### 必需观测

应用按需提供本地性能快照：完整进程组内存、托管堆与分配率、GC 暂停、受控图形资源、缓存字节、任务队列长度与字节、工作器占用、数据库耗时、UI/呈现帧指标、原生音频 underrun/xrun 和最大回调耗时。

统计用有界计数与环形样本，初始最多 512 个常规性能样本；停止诊断后解除订阅。不得逐帧写日志、每首歌永久留诊断对象或默认扫描整个视觉树。

无法取得的平台指标标为不可用。UI 定时器间隔不能冒充呈现帧时；“未观测到漏音事件”不能冒充对所有设备的稳定性证明。导出由用户触发，内容本地保存，移除凭据及不必要的用户路径和文本。

### 开发验证预算

沿用用户要求：不要长时间测试。普通变更单条命令最多 60 秒，整轮验证最多 2 分钟，构建、测试、typecheck 和重跑都计入。执行前设置超时，只停止本轮自己启动的进程，不影响其他任务。

| 变更 | 最小验证 |
| --- | --- |
| 文档、命名、普通样式 | diff、引用或实际界面，不运行完整构建 |
| 契约和调度 | 定向编译与最少相关用例，关注背压、优先级、取消和租约释放 |
| 分页与数据库写入 | 小型真实数据库夹具，检查数据边界、事务与不明结果恢复 |
| 播放会话 | 相关状态转换检查；有设备时执行短真实播放 smoke |
| 歌词与动画 | 短可视操作、隐藏恢复、快速切换，记录局部更新和资源 owner |
| 原生与平台资源 | 对应目标构建或短 smoke；不顺手开启全平台长测试 |

测试只覆盖实际产品函数和故障边界，不新增逐字文案、文件行数或动画常量的大量镜像断言。保留背压、数据完整性、EOF 只推进一次、旧事件失效和资源释放等有价值的回归保护。

短测建议拆成两种互斥选择，按本轮改动选最必要的一组：

- 资源与 UI：约 45 至 60 秒，包括稳定采样、连续滚动、搜索、导航以及窗口隐藏恢复。
- 播放与扫描：约 45 至 60 秒，使用固定隔离文件集，观察播放控制、批次提交、取消和 UI 响应。

5 万曲目夹具可提前生成或复用固定快照，验证轮不重复生成。HDD 全盘导入、跨设备持续播放、睡眠恢复和长时间泄漏观测是最终验收的独立事项；需要时明确范围和预算，不能把短测写成已经完成长期验收。

短测报告必须写采样数量和场景。几次查询或几十秒观测只能筛查明显退化；样本不足时不宣称已满足可靠的 p95、长期无泄漏或长期音频稳定性。低频轻量采样可以随日常运行积累，不要求每次开发都开启长时间 benchmark。

本文定义开发约束；性能目标等待实现后的实测。文档变更只需检查内容、链接与格式，不运行项目测试或构建。

## 每次开发的检查清单

- [ ] 本次能力只有一个事实 owner，依赖没有反向引用。
- [ ] 文件按职责落点，新增模块有真实调用者，没有扩大巨型文件。
- [ ] UI 无同步 I/O 和整库驻留，高频状态只更新局部。
- [ ] 每个缓存、队列、工作器和 pending 请求有数量与字节边界。
- [ ] 资源有 owner、取消、迟到结果处理和释放时机。
- [ ] 调度有真实优先级预留，后台不会占满交互执行资源。
- [ ] 动画有时长、帧率上限和可见性规则，结束或取消后状态有效。
- [ ] 写入有确定结果或可查询提交记录，没有自动重放结果不明的操作。
- [ ] 迁移保留 ID 与数据语义，生产库不会被两个应用独立写入。
- [ ] 最小验证在预算内完成，未测平台、设备和性能边界明确记录。
