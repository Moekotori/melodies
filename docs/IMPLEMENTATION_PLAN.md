职责、资源、退出和验证入口见 [PLAYBACK_RUNTIME.md](PLAYBACK_RUNTIME.md)。本增量不改变扫描模块的阶段状态。

日期：2026-10-02

目标：建立可独立运行、可由 Avalonia 直接调用的扫描和数据库模块；减少文件属性重复读取、每曲目跨进程调用、全库驻留和重复 SQL 准备。迁移保持新旧工作区隔离。

实施前基线：新工作区只有开发文档。.NET 10 SDK 可用。旧项目已有 C++ metadata scanner 和 C# Core；普通音频哈希已取消，不能把取消哈希重复当作新优化。旧 Core 的完整扫描写入含身份、分析、歌单、分组等语义，新模块不能在缺少这些能力时宣称完整旧版等价。

边界：本轮建立独立新数据库，绝不打开或修改生产曲库；仅修改新工作区。按文件职责拆分契约、发现、metadata、扫描管线、数据库执行器、schema、分页和 CLI。既有 C++ scanner 作为可选 metadata 适配器，协议确认后复用。

实施步骤：

1. [已完成] 建工程与类型化契约，数据库只接受新格式文件，建立有界执行器与单一写入 owner。
2. [已完成] 实现索引、准备语句批量 upsert、分页和搜索；写入批次和扫描进度同事务提交。
3. [已完成] 实现目录属性一次发现、批量增量检查、有界 metadata 工作者和批量提交；取消/失败不做全库 missing 清理。
4. [已完成] 接可取消的既有 C++ metadata 适配，提供扫描、分页、统计与错误查询 CLI。
5. [已完成] 真实 SQLite/文件短测、既有 C++ 解析路径对照、5 万行大表及精度定向检查；范围见 SCANNING_PERFORMANCE.md。

资源约束：固定工作器；发现、metadata、提交均背压；页面最多 200 行；扫描进度与错误样本有界；不读取 PCM、不做全文件哈希、不抽取封面。

风险与回滚：新 schema 不是旧 ECHO 的原地升级，跨版本导入另立迁移器；不支持的格式必须报告，不能存伪造 metadata。任务取消仅保留已确认提交，只有完整且可靠的根目录扫描才允许标记 missing。回滚停止本轮 CLI，保留或删除用户明确选定的新测试数据库，不影响旧项目。

验证预算：单条最多 60 秒，整轮构建/测试/重跑累计最多 120 秒；命令有超时，只终止自己启动的进程。短测不代表三端/真实 HDD/完整 ECHO 功能验收。

## 桌面开发热更新增量（2026-10-02）

已提供根目录 `npm run dev` 入口，由 `dotnet watch` 启动 Debug 桌面窗口。HotAvalonia 3.1.5 与框架同版本的 XAML loader 仅用于 Debug；XAML 文件由开发文件监听器重新加载，C# 使用 .NET 热更新，不支持的修改自动重建并重启。入口不增加播放器运行时的 Node 或浏览器依赖。

短验证：Debug 构建 0 警告、0 错误；两次真实窗口 smoke 分别确认 XAML 保存后同 PID 更新/还原，以及修改后的 C# 按键处理在同 PID 执行。构建与两个 smoke 累计约 27 秒。Release 的项目求值确认热更新包未被引用、`IsAotCompatible=true`；未执行 Release 发布或跨平台验收。临时修改均已还原，验证只停止自己启动的进程树。

使用和边界见 [README](../README.md)。回滚移除 npm 开发入口与两个 Debug 包引用，不改变曲库或原生音频实现。
