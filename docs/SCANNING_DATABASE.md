# 扫描和数据库模块

## 已实现范围

当前模块可以独立扫描本地目录、提取必要 metadata、写入新格式 SQLite、执行增量复扫、分页与词前缀搜索。Application/Contracts 无 Avalonia 依赖，未来 UI 可以直接调用，不需要额外 JSON/IPC 包装。

| 模块 | 文件位置 | 职责 |
| --- | --- | --- |
| 契约 | src/Echo.Contracts | 有界请求、快照、分页游标、提交回执 |
| 扫描 | src/Echo.Application/Scanning | 发现、解析、提交三个阶段及取消编排 |
| 文件属性 | src/Echo.Infrastructure/Files | 单次枚举取得属性，平台路径键，云占位与链接策略 |
| metadata | src/Echo.Infrastructure/Metadata | WAV/FLAC 有界解析及既有 C++ 协议适配 |
| 数据库 | src/Echo.Infrastructure/Library | schema、单一 writer、独立查询线程、准备语句和回执 |
| CLI | src/Echo.Cli | 可运行入口，不把界面逻辑放进 Core |

## 速度设计

未变化文件按路径、大小、修改时间和解析器版本批量判断，跳过 metadata 解析。原属性来自目录枚举，避免每个普通文件重复 stat。变化文件解析后再读取一次属性，变化中的文件拒绝入库。

WAV/FLAC 直接读取头部和有上限的文本标签，seek 跳过 PCM、图片和 padding。其他已支持格式使用持续存在的 C++ 子进程，每个工作器独占一个解析器；不重复启动每曲目解析进程。

写入在单个专用线程批量事务执行；一批内复用准备语句并重绑所有参数。普通复扫不更新曲目或 FTS，只更新有界任务进度。仅显式缺失检测建立落盘 seen 集合，不创建整库内存集合。

查询拥有独立专用读取线程，扫描 lookup 使用另一条读取通道。分页采用索引和稳定游标，不附带全库计数；游标绑定 revision，曲库改变后要求刷新，避免旧页与新页混合。

## 内存与调度边界

- 解析工作器默认 2，最多 4；不会每文件创建 Task。
- 发现队列最多 2 批，每批默认 128、最多 256，且有字符预算。
- 解析结果队列最多一个配置批次。提交达到条数/字节边界或 50 ms 延迟即 flush。
- 每个 SQLite 执行器的交互/后台队列分别最多 16/8，等待准入的调用也最多 32。
- 独立 writer 公平处理交互与后台，连续 8 次交互后提供一次后台机会。
- SQLite 页缓存 writer 8 MiB、每条 reader 4 MiB；连接关闭不留全局池。
- FLAC 文本标签块最多 256 KiB；WAV 单个必要文本标签最多 16 KiB。
- metadata 字段超限明确报告，不默默截断长标签。
- 持久任务历史最多 32 条，每任务最多 64 条错误样本。
- 不读取全音频哈希、不保留封面/PCM、不把整库 ID 或路径放进内存。

## 准确性与故障行为

所有 SQL 输入参数化。扫描状态、计数和批次回执与曲目写入同事务提交。批次序号单调递增；最新批次的同载荷重试返回原回执，异载荷复用同序号拒绝，不重复累计数据。更旧的批次拒绝重放。

同批重复路径拒绝提交。Windows 路径键按普通大小写不敏感语义生成；不同原始路径碰撞时不静默覆盖，报告 path_case_identity_required，留给后续文件身份适配处理。特殊大小写目录、路径别名和跨平台移动仍需专门迁移规则。

取消正在排队的操作可以立即返回。操作开始后由事务决定已提交或回滚，避免完成提交后却向调用者报告未执行。已确认批次保留；取消和失败不执行 missing 清理。程序再次打开独立库时把未结束任务标记为 Interrupted。

文件指纹不读取音频正文，无法检测大小和修改时间都保持不变的改写。显式 --force 重新解析。metadata header 有效不等于音频帧完整性；PCM/CRC 全文件校验是独立按需能力。

WAV 支持普通 RIFF PCM/float/extensible 及 UTF-8 INFO 标签。RF64、复杂 ID3 标签和未明确编码的非 UTF-8 INFO 的旧版兼容回退继续迁移。FLAC 支持 STREAMINFO 和 Vorbis 文本标签，跳过图片；文本 CUESHEET 和独立 CUE 复用旧 Core parser 展开分段。

MP3、AIFF、Ogg/Opus、M4A 等能力取决于配置的既有 C++ scanner 协议 v3 及实际 parser 支持。原生进程异常/超时只终止自己的进程，不能据此切换到伪造 filename metadata。复用原生解析器不代表已对所有格式/异常完成验收。

独立 CUE/osu 已接入文件夹扫描：CUE 保留旧标识与播放范围，osu 共享音频去重、标签覆盖和有界落盘缓存。尚不支持的格式保留诊断。CLI 的 issues 命令按 jobId 读取最多 64 条错误样本。

本地 WAV/FLAC 与目录发现是在固定后台工作器执行的有界同步 I/O，取消在块与文件之间检查；卡住的文件系统调用不能宣称已被强制终止。NAS 卡顿与跨平台取消时延尚未验收。原生解析取消通过终止自己的进程实现。

完整缺失检测限定在扫描根目录的索引范围内。目录无权限、链接被排除、云文件不在本地、metadata 错误、取消与失败均不会把旧曲目标为 missing。没有默认删除用户曲目。

## 数据迁移边界

本数据库有独立 application_id 与版本化迁移，虚拟来源从 schema 7 开始保存，目前大库优化升级到 schema 18。遇到旧 ECHO 或其他格式直接拒绝原地写入。新旧程序不同时自主写一份生产库。CUE/osu 来源已经保存，不代表已迁移旧 Core 的全部分析身份、歌单、封面、手动标签和远程同步。多 TB 约束、目录落盘去重及本轮验证见 [LARGE_LIBRARY_SCANNING.md](LARGE_LIBRARY_SCANNING.md)。

迁移器后续按开发文档实现，保留旧 ID、用户数据和备份。不要把新数据库结构直接覆盖到旧数据库。

## 验证与性能证据

Smoke 使用真实临时 SQLite、真实 WAV 标签文件和 FLAC metadata 夹具，覆盖增量、排序分页、搜索、变更、旧游标、取消、不完整扫描、缺失检测、提交回执、唯一 owner、持久化和旧库拒绝。

性能对照分两种：同一新 schema/FTS/持久化设置下的逐条事务与批量事务；同一组 WAV 的直接头部解析与现有 C++ scanner 热进程 stdio 解析。后者是真实旧解析组件对照，前者是对照模型，都不是完整旧 ECHO 与新播放器的全功能端到端排名。

结果写入本次 misc/ 验证目录的 results.json。夹具/热缓存、样本量和未测平台需要与数字一起报告；不得把短测声称为真实 HDD 或长期内存验收。
