# 扫描和数据库模块

## 已实现范围

当前模块可以独立扫描本地目录、提取必要 metadata、写入新格式 SQLite、执行增量复扫、分页与词前缀搜索。Application/Contracts 无 Avalonia 依赖，未来 UI 可以直接调用，不需要额外 JSON/IPC 包装。

| 模块 | 文件位置 | 职责 |
| --- | --- | --- |
| 契约 | src/Echo.Contracts | 有界请求、快照、分页游标、提交回执 |
| 扫描 | src/Echo.Application/Scanning | 发现、解析、提交三个阶段及取消编排 |
| 文件属性 | src/Echo.Infrastructure/Files | 单次枚举取得属性，平台路径键，云占位与链接策略 |
| metadata | src/Echo.Infrastructure/Metadata | WAV/FLAC 有界解析及既有 C++ 协议适配 |
| 数据库 | src/Echo.Infrastructure/Library | schema、单一 writer、独立查询线程、准备语句和回执 |
| CLI | src/Echo.Cli | 可运行入口，不把界面逻辑放进 Core |

## 速度设计

未变化文件按路径、大小、修改时间和解析器版本批量判断，跳过 metadata 解析。原属性来自目录枚举，避免每个普通文件重复 stat。变化文件解析后再读取一次属性，变化中的文件拒绝入库。

WAV/FLAC 直接读取头部和有上限的文本标签，seek 跳过 PCM、图片和 padding。其他已支持格式使用持续存在的 C++ 子进程，每个工作器独占一个解析器；不重复启动每曲目解析进程。

目录扩展名直接以 span 查询已有的大小写不敏感集合，不为每个目录条目创建字符串或遍历整张扩展名表。WAVE/BWF 使用 WAV 头部快路径。先遍历 CUE 定义，再处理物理音频，避免跨目录引用受遍历顺序影响；常规目录仍为定义/音频两次文件枚举，只有存在 osu 定义的目录额外枚举谱面。此顺序会先完成定义发现，再导入普通音频，不宣称大库首次出曲延迟已达标。

CUE 引用、需保护的目录和谱面目录由一次扫描持有，每个集合超过 1024 项或 128 Ki 字符后转临时 SQLite，页缓存各 1 MiB；scratch 写入复用同一事务，不逐项 autocommit，正常结束、取消或提前释放枚举器均释放并删除。音源属性仍按活动目录缓存最多 256 项。同音源分轨复用工作器已有 metadata 缓存；不创建全库内存快照。

写入在单个专用线程批量事务执行；一批内复用准备语句并重绑所有参数。普通复扫不更新曲目或 FTS，只更新有界任务进度。仅显式缺失检测建立落盘 seen 集合，不创建整库内存集合。

查询拥有独立专用读取线程，扫描 lookup 使用另一条读取通道。分页采用索引和稳定游标，不附带全库计数；游标绑定 revision，曲库改变后要求刷新，避免旧页与新页混合。

## 内存与调度边界

- 解析工作器默认 2，最多 4；不会每文件创建 Task。
- 发现队列最多 2 批，每批默认 128、最多 256，且有字符预算。
- 解析结果队列最多一个配置批次。发现与提交预算均包含虚拟来源字段及 JSON 转义的保守上界；提交达到条数/字节边界或 50 ms 延迟即 flush，避免合法的长中文 CUE 标签使整批越过 writer 预算。
- 每个 SQLite 执行器的交互/后台队列分别最多 16/8，等待准入的调用也最多 32。
- 独立 writer 公平处理交互与后台，连续 8 次交互后提供一次后台机会。
- SQLite 页缓存 writer 8 MiB、每条 reader 4 MiB；连接关闭不留全局池。
- 托管 FLAC 文本标签块最多 256 KiB；超过快路径预算、标签编码不兼容或带 ID3 前缀时交由有界原生读取器。WAV 单个必要文本标签最多 16 KiB。
- metadata 字段超限明确报告，不默默截断长标签。
- 持久任务历史最多 32 条，每任务最多 64 条错误样本。
- 不读取全音频哈希、不保留封面/PCM、不把整库 ID 或路径放进内存。

## 准确性与故障行为

所有 SQL 输入参数化。扫描状态、计数和批次回执与曲目写入同事务提交。批次序号单调递增；最新批次的同载荷重试返回原回执，异载荷复用同序号拒绝，不重复累计数据。更旧的批次拒绝重放。

同批重复路径拒绝提交。Windows 路径键按普通大小写不敏感语义生成；不同原始路径碰撞时不静默覆盖，报告 path_case_identity_required，留给后续文件身份适配处理。特殊大小写目录、路径别名和跨平台移动仍需专门迁移规则。

取消正在排队的操作可以立即返回。操作开始后由事务决定已提交或回滚，避免完成提交后却向调用者报告未执行。已确认批次保留；取消和失败不执行 missing 清理。程序再次打开独立库时把未结束任务标记为 Interrupted。

文件指纹不读取音频正文，无法检测大小和修改时间都保持不变的改写。显式 --force 重新解析。metadata header 有效不等于音频帧完整性；PCM/CRC 全文件校验是独立按需能力。

WAV/WAVE/BWF 快路径支持 RIFF、RIFX、RF64/BW64、PCM/float、PCM/float Extensible 有效位深、INFO 别名/编码与 bext 基本字段。压缩 WAV、ID3 和复杂结构通过有界原生探测确认实际编码；16 位立体声仅嗅探最多 64 字节，识别 DTS/IEC61937 伪装 PCM 后交给原生。支持矩阵、预算和未覆盖项见 [WAV 扫描兼容性](WAVE_SCANNING.md)。FLAC 支持 STREAMINFO 与 Vorbis 标签，跳过图片；独立 CUE、文本 CUESHEET 和原生二进制 CUESHEET 均可展开，包括单轨。明确存在的文本 CUESHEET 优先，损坏时不静默改用二进制结果。

CUE 支持多文件、文件内/跨文件 TRACK、原始 75 fps 帧 INDEX、单引号及转义、带空格文件名、混合数据轨和 leadout 边界。编码包含 UTF-8、UTF-16/32 及常见中日韩/西文代码页；无声明代码页以能精确匹配的引用文件辅助判别，无法从 ASCII 文件名可靠推断所有标签的历史编码。重复轨号、倒序/无效时间、歧义的无损替代均作为该定义的错误，不静默丢轨。带可识别引用的坏 CUE 保护对应物理音源，继续扫描其他音频；引用完全不可判定或定义无法读取时保守推迟该目录的普通音频，其他目录继续，任务不做 missing 清理。

CUE/FLAC 发现指纹现为 cue-discovery/v5，使已有来源下次扫描应用更新后的 CUE 元数据规则，不要求 force，也不使普通 WAV 等全量失效。

MP3、AIFF、Ogg/Opus、M4A 等能力取决于配置的既有 C++ scanner 协议 v3 及实际 parser 支持。原生进程异常/超时只终止自己的进程，不能据此切换到伪造 filename metadata。复用原生解析器不代表已对所有格式/异常完成验收。

独立 CUE/osu 已接入文件夹扫描：CUE 保留旧标识与播放范围，osu 共享音频去重、标签覆盖和有界落盘缓存。尚不支持的格式保留诊断。CLI 的 issues 命令按 jobId 读取最多 64 条错误样本。

显式忽略 CUE/FLAC 时，通过虚拟路径索引按最多 64 条且约 128 Ki 字符分页读取已有分轨，提交类型化 Preserved 条目，只保护已有记录与 seen 状态，不刷新媒体指纹或创建曲目；不打开被忽略的定义。已有物理音源受抑制，避免整轨替换旧分轨；有来源索引时同目录其他音频继续导入，旧记录缺来源时保守推迟该目录。损坏 CUE 也复用旧索引保护，覆盖当前文本已无法列出引用、而旧音源在其他目录的情况。这复用现有 scan_seen 与事务，无数据库 schema 变更。Core 现有的整库忽略规则仍会关闭全量 missing 清理。

每个读取工作器的来源 memo 限 128 项及估算 512 KiB，成功与已确认的文件失败均按音源大小/mtime 复用；osu 的宽松 MP3 读取与普通/CUE 严格策略分开建键。缓存命中检查取消；取消、协议错误与未确认清理不缓存，工作器释放清空 memo。CUE 单轨歌手依次采用 TRACK PERFORMER、整张 CUE PERFORMER、物理标签；单轨歌手不写成专辑身份，保留合辑归组。物理总时长未知时可采用明确的 CUE 结束边界，末轨未知时长继续保持 0，不伪造音频事实。

原生传输故障确认子进程退出后，下一文件可重新启动读取器，绝不自动重放上一请求；单个工作器每次扫描最多累计 8 次传输故障，达到预算明确终止任务。协议不兼容、程序不可用和清理未确认直接作为基础设施故障停止流水线，不累计成剩余文件的媒体错误；即使同时收到用户取消，也不把未确认清理伪装成普通取消。失败任务不做 missing 清理。

本地 WAV/FLAC 与目录发现是在固定后台工作器执行的有界同步 I/O，取消在块与文件之间检查；卡住的文件系统调用不能宣称已被强制终止。NAS 卡顿与跨平台取消时延尚未验收。原生解析取消通过终止自己的进程实现。

完整缺失检测限定在扫描根目录的索引范围内。目录无权限、链接被排除、云文件不在本地、metadata 错误、取消与失败均不会把旧曲目标为 missing。没有默认删除用户曲目。

## 数据迁移边界

本数据库有独立 application_id 与版本化迁移，虚拟来源从 schema 7 开始保存，目前为 schema 28。schema 23/24 增加扫描批次专辑维护、成员查询索引及冲突处理修复；schema 25 对齐 ECHO 的艺术家浏览规则：歌曲艺术家拆分明确合作署名，专辑艺术家保留完整署名，缺失专辑艺术家时使用既有专辑归属。schema 27 参考 Roon 的文件标签分隔原则，默认按分号与 NUL 拆分，不从名字中的逗号、斜杠或合作词推断人物；既有 v25/v26 库重建歌曲艺术家及含 NUL 的专辑署名索引，更早版本一次性重建两种分组。升级已有库先做一致性备份，再按每批 200 首重建派生索引并更新 revision，不改媒体标签、曲目 ID、专辑 ID 或收藏及历史。遇到旧 ECHO 或其他格式直接拒绝原地写入。新旧程序不同时自主写一份生产库。CUE/osu 来源已经保存，不代表已迁移旧 Core 的全部分析身份、歌单、封面、手动标签和远程同步。多 TB 约束、目录落盘去重及验证见 [LARGE_LIBRARY_SCANNING.md](LARGE_LIBRARY_SCANNING.md)，本轮配对性能结果见 [SCANNING_PERFORMANCE.md](SCANNING_PERFORMANCE.md)。

歌曲艺术家采用保守的文件标签规则：分号和 NUL 是边界；重复 ARTIST 值保持独立参与者，当前 FLAC 读取器以分号连接这些值。逗号、斜杠、&、+、乘号、feat/with/x 与括号内容默认保留，避免把 MAN WITH A MISSION、Brother x Sister、Tyler,the Creator 或 AC/DC 拆错。本项目仍规范化全角字符、空白与不可见字符，同一曲目按既有身份键去重，保留首次展示名；超过 64 个不同参与者保留完整署名，不截断。FLAC 同时识别 ALBUMARTIST、ALBUM_ARTIST 和 ALBUM ARTIST，读取版本提升后在下次扫描时重新读取旧记录。原始文件不写回。识别与派生索引属于 Core，Control 不另做拆分。

参考：[Roon 导入设置](https://help.roonlabs.com/portal/en/kb/articles/import-settings)、[文件标签最佳实践](https://help.roonlabs.com/portal/en/kb/articles/file-tag-best-practice)、[元数据模型](https://help.roonlabs.com/portal/en/kb/articles/metadata-model)。Roon 文档支持自定义及多字符分隔符，并将展示署名、主要艺人和其他角色关系分别建模。schema 28 已接通以下文件标签规则与本地人员关系；没有引入 Roon 的在线身份库，也不宣称复刻其私有实现。

- 自定义分隔符属于 Core 曲库设置，最多 16 个、每个 1–16 字符，允许多字符并优先匹配较长项；NUL 始终生效，独立的重复 ARTIST 标签不依赖分隔符。默认仅分号，不猜测 feat/with/x/逗号/斜杠。
- 通过艺术家页面“人员与角色”或“设置 → 维护与恢复 → 曲库维护”修改。任务由 Core 接受并持有，以 200 首分页处理；同一 writer 事务更新设置、歌曲艺术家和人员角色索引，取消或失败回滚，提交后只增加一次 revision。控制端关闭不会取消已接受任务，操作回执防止不明结果被重复执行。专辑艺术家完整署名、曲目身份与个人状态保持。
- ARTIST、ALBUMARTIST、COMPOSER、CONDUCTOR、ENSEMBLE、PERFORMER、SOLOIST、FEATURING、制作类标签及 PERSONNEL 导入人员关系。PERSONNEL 按最后一个 ` - ` 分开名称与角色，同一人允许多角色；主要表演者、表演者、团体、创作者、指挥、制作人员分别归类，未识别角色保留原文与 Unknown 分类。曲目与专辑范围分别保存。人员以本地规范化名称关联，尚无同名异人消歧或在线身份合并。
- 原始署名标签落盘，改变分隔符无需重读媒体。已有库升级只回填可确认的主要艺人关系；角色需要下次扫描或显式重新读取标签（parser v6）。托管 FLAC 与原生 Vorbis/ID3 路径保留原始多值；FFmpeg 回退只能提供容器实际暴露的字段，不保证恢复已丢失的重复标签。
- 查询通过静态类型化 Core 契约，人员、人员参与曲目、曲目署名各页最多 100 条，角色摘要最多 16 种；Control 不打开业务数据库。每曲最多 64 个原始标签、单值 2048 字符、合计 16 Ki 字符、派生关系最多 256 条；角色文本纳入扫描批次与来源 memo 内存预算。

## 验证与性能证据

Smoke 使用真实临时 SQLite、真实 WAV 标签文件和 FLAC metadata 夹具，覆盖增量、排序分页、搜索、变更、旧游标、取消、不完整扫描、缺失检测、提交回执、唯一 owner、持久化和旧库拒绝。

性能对照分两种：同一新 schema/FTS/持久化设置下的逐条事务与批量事务；同一组 WAV 的直接头部解析与现有 C++ scanner 热进程 stdio 解析。后者是真实旧解析组件对照，前者是对照模型，都不是完整旧 ECHO 与新播放器的全功能端到端排名。

结果写入本次 misc/ 验证目录的 results.json。夹具/热缓存、样本量和未测平台需要与数字一起报告；不得把短测声称为真实 HDD 或长期内存验收。
