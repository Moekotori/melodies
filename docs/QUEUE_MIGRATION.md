## 来源和入口

只读对照 `D:/ECHO/src/renderer/pages/QueuePage.tsx`、`components/player/PlaybackQueueDrawer.tsx`、`stores/PlaybackQueueProvider.tsx`、`playback/queueNavigationPolicy.ts`、`playback/playbackModePresentation.ts` 和 `pages/queue/queuePageRows.ts`。

入口：侧栏“队列”和“历史”、播放栏队列图标、更多菜单、Ctrl+Q。专辑详情支持整张专辑或单曲“下一首播放 / 添加到队列”。页面沿用旧版的当前歌曲、下一首预览、四种播放策略、搜索和虚拟化曲目表；抽屉复用同一队列状态和行模板。

| 已迁移行为 | 语义 |
| --- | --- |
| 队列身份 | itemId 表示一次排队，同一 trackId 可以有多个 occurrence；专辑重放产生新 itemId |
| 下一首播放 | 添加按 FIFO 插入待播段；优先于随机播放；离开后移除临时 occurrence 并回到原队列 |
| 四种策略 | 顺序 / 随机 / 单曲循环 / 列表循环；播放栏按旧版顺序轮换；Native Host 执行真正的 EOF 推进 |
| 上一首 | 顺序专辑跳过临时 occurrence，返回前一专辑曲目；其他情况使用播放历史 |
| 编辑 | 多选移除、移动到下一首、拖动和 Alt+↑/↓ 排序、播后移除及取消、单步撤销 |
| 清空和移除当前项 | 当前音频继续；Native 保留隐藏当前项作为推进锚点，停止对已脱离队列的歌曲循环 |
| 页面 | 专辑上下文保留此前曲目，普通队列显示当前及后续；搜索不合并重复 occurrence |
| 状态恢复 | schema 2，仍读取 schema 1；保存顺序、策略、历史、随机顺序和脱离队列的当前项；恢复为暂停，旧生产库不参与 |
| 系统控制 | 清空后仍可暂停当前音频；系统播放命令复用原会话，避免重建队列/丢失历史 |

## 职责和资源

- `Echo.Playback/PlaybackQueue*.cs` 是播放会话的分职责部分：结构和 Native 投影、编辑与撤销、导航与历史。所有写入和 Native 收据都走已有 64 项有界命令通道，不新增状态 owner。
- `QueueChanged` 只发布结构变化；位置事件只更新播放快照。UI 合并迟到的结构通知，不因时钟刷新复制行或同步 Native 队列。
- 当前播放窗口最多 1000 项，Native 队列结构序列化最多 384 KiB；序列化之前限制字符串总量，避免先生成超大消息。编辑撤销只持有一个有界旧快照。历史最多 500 项，并限制其文本预算；图片不进入队列对象。
- Native 投影允许额外保留一个正在播放的脱离项。普通顺序不复制整库；随机投影有稳定顺序，并优先保留待播临时项。
- `QueueViewModel` 由播放器视图拥有，最多 1000 条展示 DTO / 500 条历史 DTO；`ListBox` 使用 `VirtualizingStackPanel`，外层不套无限高度 ScrollViewer。
- `QueueArtwork` 复用已有 32 MiB / 192 条目封面缓存及单解码工作器；离开视觉树取消请求，迟到结果释放，当前可见控件持有租约。UI 不读取文件和数据库。
- Application 的 `PlaybackRuntime` 负责会话与新应用状态库生命周期，结构保存合并；UI 脱离不负责关闭共享音频会话。重启、关闭和恢复使用已有生命周期边界。
- 用户命令取消在准入/开始前生效；已发出的 Native 修改等待确定收据，不因取消自动重放。未确认修改不发布为成功队列。

## 验证

短测工具：`tests/Echo.Playback.Smoke` 与 `tools/Echo.Preview --queue misc/queue-validation/previews`。测试数据和日志全部在 `misc/`，无凭据。

行为检查覆盖重复歌曲 occurrence、FIFO、随机待播优先、专辑上一首、手动跳出单曲循环、列表循环、清空保留输出、撤销与批量排序、播后移除、未确认收据、取消、窗口上限、重复和迟到 EOF、checkpoint 恢复。30 个位置事件不触发队列结构通知或 `queue.set`。

真实 Windows Native Host 使用静音 WAV：实际 EOF 顺序为插入 B1 → B2 → 原队列尾部，并确认临时项消费；基础解码、输出、暂停、seek、恢复和停止也执行短 smoke。这不是长期音频稳定性或跨设备验收。

原生 Headless 截图使用构造曲目和封面夹具，验证真实 Avalonia 控件和绑定，不代表这些示例曲目的真实解码。覆盖浅/深色、抽屉、历史、空队列、窄窗口、1000 项虚拟化及位置更新不重建行。完整验证结果与本轮累计时间见日志及交付说明。

最终 UI 短测通过：包含真正的 Headless 鼠标拖放、Ctrl+Q/Esc、绑定操作、1000 项 / 4 个 realized 行；UI smoke 约 1.7 秒。最终 Windows 播放 smoke 约 4.6 秒。全桌面构建成功，尚有歌词/设置抽屉运行时 XAML loader 的三个已有构造器警告。包括并行工作中临时引用错误与本轮修正后的重跑，验证累计约 80 秒，单条均未超过 60 秒。未跑完整打包、全量测试或长 soak。

最后补齐历史文本边界后，`Echo.Playback` 定向构建通过。整工程重跑在并行扫描模块的 `TrackSourceJson.cs` / `OsuScanFacts` 类型缺失处停止；该错误不属于队列变更，未改动扫描实现。上述 UI/真实播放通过记录属于此前可编译的工作区快照，不能称最新所有并行模块均通过构建。
