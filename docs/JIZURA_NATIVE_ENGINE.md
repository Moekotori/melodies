# Afterglow 原版引擎接入

2026-10-02。旧版 12 个歌词样式 ID 保留；Afterglow 当前源码共 23 个外观，包含此前漏掉的 `rhythm` 音游。

## 实际调用

独立全客户区 `LyricsView` → `JizuraSceneControl` → 单个 `JizuraSceneWorker` → `Echo.Visuals.JizuraEngine`。选择其他样式时释放引擎；退出页面取消工作、丢弃迟到画面并释放原生资源。没有浏览器、Node、原生音频变动或旧曲库访问。

`tools/Import-JizuraVisualEngine.cjs` 只读旧工作区并导入实际脚本顺序：91 个脚本、3,249,940 字节，23 个主题定义。逐文件 SHA-256 在 `src/Echo.Visuals/Resources/Jizura/manifest.json`；上游 revision `8da975fb362d966b065217618aedafd5a35a39e0`，MIT 授权原文同时嵌入模块。原先 22 个近似方向绘图已移除。

Jint 执行原版规划、布局、场景、相机、装饰、转场和逐词效果代码；Canvas2D 调用由 Skia 绘制。只替换高分配像素循环：四张随机灰度纹理、纸张噪点，以及原版字形的 60 阈值、八邻域连通分解、两次边缘扩展、小碎片合并算法。替换在 `JizuraEngine` 运行时明确检查原文标记，不修改导入的源文件。字形拆分有实际原生调用者，不是空包装。

原生桥承接路径、变换、裁切、文字、图片、线性 / 径向 / 扫描渐变、图案、混合、模糊 / 阴影、反色 / 灰度与像素读写。字形使用可用的本机字体；不能把这视为原版外部字体的等价验证。

## 调度与预算

- UI 只提交当前歌词文档引用及小请求，不读取文件、不执行规划或像素算法。
- 一个后台 worker，一个容量 1 的替换队列，最多每秒 12 次提交；忙时替换待处理请求。没有逐词任务或另一个播放时钟。
- 原版绘制仍使用真实原生播放位置及最多 250ms 的显示插值。真实词时间转换为排除空白的 Unicode 区间，不填入估算时间。
- 长文档每次规划最多 128 行的邻域；每行最多 512 UTF-16 字符，256 个词区间。普通阅读界面仍可访问整个受限文档。
- raster 总量最多 16M 像素，最多 1,024 画布；单调用分配约束 128MiB、8 秒与 1,600 万语句。此解释器分配约束不是进程常驻内存实测。
- 渐变按帧重建与释放；字形 / 颜色 / 纸张沿用原版有界 LRU，并将淘汰同步到原生画布。
- PNG 只用于验证输出，界面传输 BGRA 像素，避免每帧 PNG 压缩。

这些是上限和保护，不是稳定帧率承诺。部分场景解释执行仍有显著开销；完整设备帧率和长期资源稳定性未验收。
