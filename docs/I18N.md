# I18N 语言系统

日期：2026-10-02。内置简体中文、英文与“跟随系统”，支持用户自定义 JSON 语言包。入口是设置 → 通用 → 显示语言及“用户语言包”。语言代码保存到新应用自己的 `preferences.json`；旧设置文件没有该字段时继续使用系统语言。Steam 语言跟随仍属于未接入的独立能力。

## 用户自定义语言包

普通用户不需要修改源码或重新构建。在设置 → 通用的“用户语言包”中：

1. 点击“导出当前语言模板”，得到包含完整键表的 JSON。
2. 编辑 `code`、`nativeName` 与 `strings`。相同代码覆盖该内置语言的文案；新的文化代码添加一种语言。
3. 点击“导入语言包”。应用校验后安装并立即启用，语言下拉框显示“自定义”标识。
4. 点击“打开语言包目录”编辑已安装的文件，再点击“重新加载语言包”，当前窗口立即应用修改。

目录是新应用的 `LocalApplicationData/ECHO Avalonia/languages`，界面显示实际完整路径。只读取顶层 `.json`，不递归，不加载代码。直接复制 JSON 到该目录也可在下次启动或手动重载时发现；没有常驻文件监视器。

例如只改英文导航中的主页标签：

```json
{
  "code": "en-US",
  "nativeName": "我的英文",
  "strings": {
    "navigation.home": "My Home"
  }
}
```

未填写的文案优先回退到同代码内置语言，再回退到内置中文。内置资源保持只读，用户覆盖独立存放；中文覆盖不会改变旧文案的源键索引。删除或损坏所选包时，保存的语言代码仍保留，界面显示“暂不可用”；修好文件并重新加载可恢复选择，随时可以切回内置语言。

损坏 JSON、未知键、参数不一致、重复文化代码和超限包会报告并跳过，其他有效语言仍可用。相同文化代码的两个用户文件不会随机选择其中一个，需要用户移除重复文件。替换已有包使用同目录临时文件与原子重命名，并保留一份 `.bak`；失败或提交前取消不覆盖原文件。提交后取消不重放导入。对具体参数类型无效的自定义格式会回退到内置模板并缓存该回退结果。

## 开发者内置一种语言

在 `src/Echo.Desktop/Resources/Languages/` 添加 `<culture>.json`。项目通过通配符自动嵌入，启动时按 `code` 和 `nativeName` 自动发现，不需要修改语言注册表、设置选项或业务代码。重新构建并启动即可使用；这用于随发行版提供的内置包。用户自定义包使用上面的运行时目录入口。

从 `en-US.json` 复制并翻译 `strings` 的值，保留键与格式参数。`code` 使用 .NET 支持的文化代码，`nativeName` 使用语言本身的名称。也可以先交付部分翻译，例如：

```json
{
  "code": "fr-FR",
  "nativeName": "Français",
  "strings": {
    "language.followSystem": "Suivre le système",
    "queue.count": "{0:N0} titres"
  }
}
```

缺失文案从 `zh-CN` 基础包回退。系统语言按精确文化、父文化、同语言已有包、基础包解析。未知键显示键本身，便于发现开发遗漏。新增语言时需检查字体、长文案、复数和语法；窗口根据文化的 RTL 标志切换方向，具体语言的视觉排版仍需验收。

## 新功能怎样使用

先在基础包添加有语义的稳定键，例如 `albums.import.cancelled`，再在英文和其他包中加入译文。完整句子使用 `{0}` 等位置参数，允许翻译调整参数顺序；`N0` 等数字格式使用当前选中的文化。不要拼接带语法的译文片段，也不要用显示标签判断业务行为。

XAML 使用运行时资源：

```xml
<TextBlock Text="{DynamicResource navigation.albums}" />
```

含参数的文案在 ViewModel 中格式化并绑定：

```csharp
public string CountText => Text.Format("queue.count", count);
```

无参数文案使用 `Text["navigation.albums"]`。`LocalizationService` 从窗口装配传入；语言变更时仅通知依赖文案的属性，退出时撤销订阅。不要建立可变的全局 Localizer，也不要修改线程或进程的 `CurrentCulture`。

既有设置目录使用 `Translate(source)` 过渡映射，迁移键带 `ui.<view>.<hash>` 或 `text.<hash>` 前缀。它们已成为稳定键，翻译时不要重新生成。修改旧中文源文案时同步更新基础包；新增功能优先使用语义键。歌曲名称、艺人署名、歌词正文、设备名称等用户内容保留原值。

选择控件分别保存稳定值与翻译标签。语言使用文化代码，动效使用 `MotionMode`，歌词样式使用原样式 ID，字体和对齐保留既有保存值。切换语言不修改主题、歌词偏好、队列或音频设置。

## 职责、资源与性能

| 文件/模块 | 职责与所有者 |
| --- | --- |
| `Localization/LanguagePack.cs` | 不可变字符串表、文化和预解析的格式模板 |
| `Localization/LanguageCatalog.cs` | 启动前读取一次嵌入包，校验、系统文化解析、旧文案键索引 |
| `Localization/LocalizationService.cs` | 每个窗口的当前语言及变更事件；不持有控件或曲库 |
| `Localization/WindowLocalizationBinding.cs` | 主窗独立资源字典，语言变更一次替换，DataContext 更换/窗口关闭时撤销 |
| 设置、歌词选项和播放器的局部文件 | 翻译可见属性，保留原操作值，不触发曲库读取或歌词重载 |
| `Localization/UserLanguageStore.cs`、`LanguagePackJson.cs` | 用户目录的校验、单一文件操作、原子安装和完整模板导出 |
| `Settings/UserLanguagesViewModel.cs`、`UserLanguagesView` | 窗口持有的异步操作、错误状态、取消、文件选择器和重载入口 |
| `WindowPreferencesBinding` 与既有设置 store | 异步恢复、过期结果保护、有界保存，复用既有单一写入 worker |

目录是共享的只读 `FrozenDictionary`，当前两份 JSON 合计约 84 KiB。内置包最多 16 个，用户目录最多 16 个 JSON，每包 256 KiB、4096 个条目，每个字符串最多 4096 字符；语言键限于内置基础键表，用户不能创建无限的新键。格式模板最多 64 个字段、对齐宽度绝对值不超过 256、格式说明符最多 64 字符、数字精度不超过 32，避免自定义格式造成巨大显示分配。校验拒绝重复键、未知键、损坏模板及参数集合不一致，使用 `JsonDocument`，不依赖反射 JSON 反序列化。

正常桌面启动在 UI 事件循环之前读取嵌入包。查词无文件 I/O、无序列化、无遍历、无分配；含参数格式化会产生最终显示字符串。用户文件只在启动、导入、导出或手动重载时由单一活动后台操作读取，未完成时不排队；窗口退出取消，操作预算 15 秒，结果晚到后不更新已退出的窗口。恢复时先恢复已保存的语言 ID，再异步发现用户文件。窗口切换在 UI 线程内完成有界资源替换与局部设置选项重建，没有常驻工作器、轮询或逐帧语言通知。语言资源不会重建播放会话、曲库、队列行或歌词文档。

Catalog 生命周期是进程，Service 生命周期是窗口。Window binding、Settings、Motion、LyricsAppearance、Player、Queue、活动歌词页和专辑列表分别释放自己的订阅。加载阶段无持续任务；同步切换为有界操作，没有额外取消队列。桌面偏好的读取与保存沿用既有取消与释放边界。

## 已接入与后续边界

已将当前 XAML 静态中文属性移入资源，包括主壳、主页、专辑/艺人页面、播放栏、队列、设置与抽屉；设置目录、搜索、导航、主要播放/队列状态、专辑列表计数、歌词状态及样式/主题/字体/对齐选项已接入运行时语言变更。

专辑/艺人详情中的部分动态摘要、扫描动态进度、原生设备模式与诊断文字仍需要继续按职责迁移。已翻译资源条目不等于所有动态调用者都已经接入。当前不提供复杂复数规则、在线翻译、插件语言包和自动文件监听；新增语言可通过完整句子键扩展这些语法场景。没有执行 AOT 发布、三平台或实际 RTL 语言验收。

回滚入口是选择“简体中文”，无 schema 或生产曲库变更。新偏好字段是可选增量，旧版本可以忽略它；原生音频、扫描和旧 ECHO 数据库没有为此语言系统修改。

## 短验证

`tools/Echo.Preview --i18n <output>` 通过实际 Avalonia Headless 控件检查语言选择、运行时资源、设置搜索、主题操作值、歌词样式 ID/偏好稳定性、多窗口隔离、稀疏包回退、缺失键、重复键、未知键、格式参数和体积边界，并检查语言偏好写回及旧格式兼容。截图在 `misc/i18n/preview/`；生产应用不加载该工具。

构建/短测的单条时限 60 秒，整轮总预算 120 秒，仅终止本轮启动的进程。Debug 查词及切换测量记录在同目录 `results.json`；它是冻结字典微测和 Headless 最终布局测量，不能当作实机帧时、完整应用启动预算或 Release 性能验收。

运行时文案使用 Avalonia 的 [DynamicResource 与资源字典机制](https://docs.avaloniaui.net/docs/app-development/resource-dictionary)。

本轮结果：已编译的 Avalonia Headless 快照包含 756 个键，语言控件、英文设置/主页/歌词抽屉、20 次切换与偏好检查通过；查词 100 万次约 15.7 ms、0 字节分配，20 次切换加最终布局约 55.2 ms。后续新增静态文案后，当前源码核心独立编译并检查完整中英 792 键通过，100 万次查词约 16.6 ms、0 字节分配。两者是不同范围的 Debug 测量。

此前桌面与 Preview 构建通过，存在 3 条注入构造函数相关的 AVLN3001 运行时 XAML loader 警告。最后整工作区重建受同时进行的队列页面改动阻塞：MainWindow 使用了 QueueView 的三参数构造与 Dispose，但当前 QueueView 尚未提供对应接口。保留并行实现，不为语言系统覆写该页面；当前全应用编译状态不能标为通过。全部本轮构建与短测累计约 30 秒，未运行发布或长测试。
