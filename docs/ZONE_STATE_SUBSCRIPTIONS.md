# Zone 快照与分类订阅

日期：2026-10-02。

## 唯一发布 owner

`PlaybackSessionCoordinator` 在原有串行命令 lane 中发布 `PlaybackStateSnapshot`。同一帧包含会话 generation、单调版本、播放状态、对应队列快照、循环模式、请求/确认输出、时钟锚点和核心可用性。`PlaybackZone.Snapshot` 添加 Zone ID 和名称。

队列成员、当前项或模式变化时，先建立对应队列快照，再发布统一帧。控制端不用分别读取当前曲目、队列和输出配置。旧通知暂时保留给未迁移的歌词、专辑和持久化入口；新播放栏、队列视图和系统媒体控制使用统一订阅。

## 订阅与背压

`zone.Subscribe()` 在注册时原子取得完整 `Initial` 状态。之后的 `ReadAsync(token)` 返回最新完整帧及变化分类：`Playback`、`Queue`、`Clock`、`Output`。调用者可以只订阅需要的类别。

每个订阅只支持一个 reader，最多保留一个待交付帧。新帧合并待交付的变化标记，因此队列变化后到达的时钟消息不会掩盖队列变化。完整帧可直接用于重新同步，不需要依靠连续 delta 重建状态。会话最多 32 个订阅；队列视图、播放栏、系统媒体控制各占自己的名额。创建控制端中途准入失败时释放已取得的订阅。

发布路径不执行订阅者回调，也不等待 UI 或平台 I/O。订阅共享有界只读队列引用，不复制整条队列到每次进度更新。等待取消仅取消当前 reader 的等待；断开时明确 Dispose 订阅。核心退出先发布不可用与撤销后的设备事实，再结束订阅。

## 控制端更新

播放栏在 UI dispatcher 前再次合并帧与分类，只在对应类别变化时更新标题、曲目信息、模式及输出摘要。时钟更新只刷新局部进度；队列视图只接收结构变化。首次连接立即应用注册时的完整状态，重连重新注册；generation 区分不同应用会话。

音量、元数据或队列更新不重设原生位置锚点。只有位置、播放状态或 operation 变化才建立新的单调时间锚点。权威播放位置、EOF 和设备事实仍属于 Native Host。

## 验证与范围

`dotnet run --project tests/Echo.Playback.Smoke -- --state-only` 覆盖快照一致性、纯进度分类、慢端合并、重连、时钟锚点、准入上限、退出和原有核心生命周期。

`tests/Echo.Playback.UiSmoke` 覆盖真实静音 Native Host 的两个控制端、准入失败后的名额回收、断开/重连及注入核心的窗口生命周期。此检查关闭自己的动效，不用于证明动画和主题的验收状态。

目前是同进程类型化订阅；尚未增加网络发现、配对、远程命令协议或音频传输。
