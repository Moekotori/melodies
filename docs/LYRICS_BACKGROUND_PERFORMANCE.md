# 歌词背景性能优化（2026-10-19）

本次只改 Control 展示调度和 Echo.Visuals 的绘图资源复用。保留原版 shader、时间推进、调色、帧率、分辨率、交互及过渡，不增加 Core / 音频 owner 或后台分析任务。

## 变化与生命周期

- 一张封面各 mip 级的不可变采样器由该纹理持有，上传时创建、替换 / 删除时释放。program 仅在纹理代次 / 绑定变化时重新绑定，不每帧重建 16 个采样器与尺寸数组。原有最多 4 张纹理 / 16MiB 预算保持不变。
- uniform 数组按 program 中实际存在的名称和长度复用；标量直接赋值，移除每帧 LINQ 数组。只复用输入缓冲，SKRuntimeEffect 仍为每帧建立不可变输出。
- 背景配置使用值类型 key。仅背景配置或动效策略改变时强制提交；歌词行、字号等变化不再额外驱动背景。普通动画仍按原有有界 timer 更新。
- 静态图片不接收无效指针绘图；仅有指针交互的封面 shader 处理 move / press / leave。静态图片不会跟随歌词设置或鼠标移动重复包装 picture。
- 频谱仅在权威 timestamp / 数据引用改变时复制最多 32 项；工作器复用该快照的 JSON，脚本只在输入串变化时重新解析。隐藏或切走后清理快照引用。旧请求仍拥有自己的不可变数组。
- 将引擎返回的独占不可变 SKPicture 直接移交 SourceSceneFrame，去掉一层重复 recorder。窗口与渲染操作的引用计数保持不变；关闭后的迟到帧直接释放。
- 新缓存均绑定当前 program / texture / scene 生命周期，没有全局缓存、队列增长或额外纹理副本。

## 同口径短测

macOS arm64，Release，同一 factory-dark 封面、640×360、每个场景先预热 12 帧，再测 120 帧。`--profile` 使用相同代码测优化前 / 后，输出 CPU 中位数、p95、当前线程托管分配。计入 Draw 内的 Canvas 绘制；最终 SKPicture 回放、GPU 合成、JavaScriptCore 的原生堆、全应用进程树 RSS 不在该指标内。

| 场景 | 托管字节 / 帧：前 → 后 | CPU p50 毫秒：前 → 后 |
|---|---:|---:|
| 涟光及同类封面 shader | 15,705 → 9,233（约 −41%） | 涟光 0.026 → 0.023 |
| 流光 | 7,631 → 5,711（约 −25%） | 0.021 → 0.019 |
| 封面流动 | 6,273 → 5,201（约 −17%） | 0.015 → 0.014 |
| 广度优先搜索 | 6,922 → 5,266（约 −24%） | 0.011 → 0.010 |
| 几何氛围 | 188,005 → 188,005 | 3.727 → 3.661 |

耗时为本机短测，微小变化可能处于波动范围；几何氛围的 Canvas 热路径分配没有下降，不据此宣称整体 CPU、GPU、FPS 或驻留内存提高固定比例。完整 16 项结果在忽略目录 `misc/lyrics-background-sync/perf/measurements.json` 与 before / after 日志。

## 必要验证

- 16 个场景输出及 8 个切歌中间态，共 24 个 PNG 与优化前逐字节一致。
- 每个场景保留先前交付的 picture，在继续绘制 120 帧、替换封面三次后重新绘制，仍与最初输出一致，检查输入复用与纹理释放没有改写已交付帧。
- 实际 Avalonia 控件检查连续出帧、减少动效、隐藏释放 / 恢复、设置及保存；新增静态图片在字号 / 翻译变更和指针移动后不交付新背景帧的检查。
- 聚焦 Release 构建通过（7 项已有 XAML runtime-loader 提醒）；macOS arm64 AOT 背景引擎发布并运行涟光 / 几何场景与旧帧稳定性检查。
- 不代替真实桌面客户端、长时间播放、其他操作系统或完整进程树内存测量。

重现短测：

```sh
dotnet run --project tools/Echo.BackgroundPreview -c Release -- misc/background-profile --profile
```
