# 艺人墙迁移

日期：2026-10-02。入口：侧栏“艺术家”。只使用新应用格式曲库，未读写旧 ECHO 生产库。

## 来源与页面

对照旧版 `ArtistsPage.tsx`、`artistVisual.ts`、`songs.css`、`artist-monogram.css`、`SteamArtistDetailView.tsx`、`artist-detail.css` 和 `steam-artist-hero.css`。

墙面保留标题/总数、搜索、视图选项、排序及方向。头像存在时圆形显示；没有头像时使用旧版的裸字母/汉字排版，西文字体 Times New Roman，中文使用应用字体。卡片头像区域 124，横向间距 22，行间距约 30；名称和数量居中。支持方向键、Home/End、Enter/Space，搜索防抖 120 ms，回车立即提交。

提供参与艺人和专辑艺人两种分组、名称/曲目数/专辑数/最近入库四类排序，以及显式的专辑封面回退选项。默认不以专辑封面冒充艺人头像。

详情采用旧版宽横幅、底部标题/操作、概览/专辑标签。曲目有界读取，复用既有曲目行、收藏和播放操作；专辑页复用专辑分页及封面缓存。共用 `DetailNavigator` 的有限历史，支持艺人到专辑及返回。网络画像、在线介绍、关联艺人、演出、聆听排序和旧版模糊合并尚未完整迁入。

## 数据、所有权与边界

- 契约：`Echo.Contracts/Library/ArtistModels.cs`。
- 基础设施：`ArtistSchema`、`ArtistIndexWriter`、`ArtistCredits`、`ArtistQueries`；随 schema v4 阶段安装，保留后续迁移阶段。
- 桌面：`Features/Artists` 负责局部状态、可见卡片与详情；Bootstrap 共用原有数据库实例和封面服务。
- 所有索引、扫描及写入继续由原有 writer lane 执行，没有第二个数据库写入 owner。

`artist_tracks` 保存去重的参与关系，`artist_albums` 增量维护同一艺人同一专辑的曲目数；触发器在同一事务里更新曲目数、不同专辑数和总时长。扫描 metadata 提交维护索引，missing/delete 移除关系。初始化按每批 200 行回填，不创建整库对象数组。

旧版明确署名分隔规则已迁入：feat./ft./featuring/with、分号、非短乐队名的斜杠等。保留 AC/DC、数字斜杠和带空格逗号/ampersand 的乐队名；同一曲目重复署名只计一次。名字按 NFKC、空白/零宽字符清理及 invariant 小写生成稳定查询键，未移植旧版模糊相似度合并。超过 64 个分段的特殊署名按原始整体保留，避免静默丢人。

参与艺人的专辑页包含其参与的本地专辑；专辑艺人视图限制为对应专辑署名。专辑版式复用现有实际查询、稳定 ID 和详情入口。

已有 v1–v3 新应用库在 v4 安装前用 SQLite Backup API 保存 `.before-v4-*.sqlite` 一致性快照；v4 数据变化用一个事务回填。旧 ECHO 生产格式仍被 application_id/schema 检查拒绝。

## 资源和取消

- 单页最多 200，艺人墙最多三页/600 DTO；筛选、排序、搜索和导航采用 generation/取消。
- 只有视口和上下各一行建立卡片；正常滚动复用卡片，回收池最多 24，隐藏/离页清空。
- 视口拥有有限 ScrollViewer；不把整个艺人墙置于无限测量的外层滚动容器。
- 图片与专辑/歌词共用一个固定工作器、最多 64 个请求、32 MiB/192 项缓存；取消后迟到图不重新建立 owner。
- 本地头像候选为对应目录的 artist.jpg/png/webp，读取最多 4 MiB。只选有该艺人专辑署名的目录，避免把合作艺人的目录照片错误归给参与者。没有可信路径或读取失败时回退字母。
- 队列组装最多 1000，批次最多 200；超过数量时在界面说明本次范围。保留虚拟曲目的实际音源及片段边界，不以虚拟路径直接打开音频。
- SQLite 支持排队取消和批次/读行边界取消；不宣称可立即中止已进入 SQL/解码内部的工作。

## 短测与当前证明

生成的真实 SQLite 包含 50,000 首曲目、10,000 初始艺人。通过合作署名、乐队名、重复署名、两种分组、不同专辑计数、艺人专辑/曲目查询、metadata 改署名、missing/恢复、revision、取消和四类排序索引。

初始 8 个深页样本（第 9600 位附近）中位 0.90 ms、最大 2.37 ms；生成 metadata 提交约 11.36 秒，不包含真实文件发现/解码，不能作为完整扫描或旧版对照。

原生 Avalonia Headless 明暗截图与短测已通过：热壳导航到首批数据/卡片 251.2 ms；连续深页跳转驻留 600 DTO，末次 35 个卡片，检查上限 60；搜索、分组、空结果、隐藏/恢复、窄窗口、艺人/专辑往返及释放。首屏数值是 Debug 单样本、1440×900/100%/Skia，不是 Release p95、进程冷启动或真实呈现帧率。截图使用示例曲库和一张生成的头像示意图。

最后一轮共享工作区新增的歌单/主页/浮窗/快捷键代码持续变动，完整 Preview 构建出现与本模块无关的阶段性缺项；已通过的原生 UI 短测不能冒充当前整棵工作树的最终构建验收。后补的控件池/键盘深页焦点检查和升级备份检查需在并行代码收敛后复核。本轮构建、失败修复与短测累计仍控制在 120 秒内；未进行打包或长测，未结束其他任务的进程。

日志、生成 SQLite 和原生预览均在 `misc/artist-wall-validation/`。真实图库、完整网络艺人功能、设备播放和跨平台行为仍需后续验收。

## 回滚

停用 artists 导航即可保留其他页面。数据库降级使用升级前的一致性快照并保持新旧应用隔离，不让旧 ECHO 生产应用打开新格式库。旧版艺人页面与在线资料实现保留至完整迁移验收。
