# 队列界面重新对齐

2026-10-02。用户反馈第一版外观与旧版差距过大，并指出系统完成度不足；本轮以整体风格和布局为重点，不把核心状态测试当作体验完成证明。

## 当前证据

1. 原版视觉参考：只读服务运行 `D:/ECHO/out/renderer` 的原始页面，在独立 localhost origin 用有界曲目样例进入“队列”，保存于 `misc/queue-rework/01-original-renderer-dark.png`。没有操作正在运行的旧 ECHO，也没有写入旧曲库。没有 Electron IPC，因此这是 Renderer 布局参考，不能用于验收旧版音频和曲库操作。
2. 第一版原生界面：本轮重新运行既有预览，截图在 `misc/queue-rework/before/`。该预览使用此前的编译快照，文案资源装配也与最新主窗口有差异，不能称最新应用的完整截图。
3. 改后队列：当前队列 C#/XAML 已独立编译，挂入此前可运行的原生 shell，截图在 `misc/queue-rework/after/`。与原版参考使用相同曲目样例，播放状态模拟。深/浅色和窄窗均实际渲染；窗口尺寸与原版浏览器参考不同，不做像素等价声明。
4. 播放行为：定向短测通过待播放队列首次启动、播放模式选择/编辑不提前启动音频、FIFO、独立 occurrence、清空保留输出、重复/迟到 EOF、SQLite 恢复和真实 Native Host EOF。截图不承担这些行为证明。

## 改动

- 恢复标题与当前歌曲在同一主体区域，补回队列数量/总时长、下一首箭头和音质/来源信息。
- 播放模式使用旧项目同版本 Lucide 图标与底部选中线，避免依赖透明 `EchoSelected` 导致状态不可辨。
- 列表按旧版职责展示曲目/艺术家、音质、来源、时长、拖动入口、行内播放和菜单。行高回到 64，恢复普通点击单选、Ctrl/Shift 多选及 Alt+N。
- 页面独立拥有搜索、选择和历史投影，抽屉继续使用其自己的投影；不再通过打开抽屉改写历史页的展示模式。
- 编辑与模式选择在音频尚未启动时仅修改队列事实；播放键可从已添加的队列启动，并遵循实际显示的随机候选。
- 封面仍复用有界缓存，UI 不做文件读取；原有队列事实 owner、Native 收据和取消边界保留。

## 尚未通过的验收

- 最新完整工作区包含正在修改的首页、歌单、歌词、多窗口等模块，构建先后遇到缺失类型、临时接口和文件锁。没有终止其他任务启动的桌面进程。本轮最终采用独立队列预览，不能宣称整应用构建及验收通过。
- 改后页面/抽屉的完整交互 smoke 已随独立投影更新，但尚未在本轮最新整工程执行通过；不能沿用第一版的 UI 通过结论。
- 窄窗主体仍占较多高度，需进一步收紧；整应用的其他页面、保存命名队列、推荐和衔接功能仍须逐项迁移和验收。
