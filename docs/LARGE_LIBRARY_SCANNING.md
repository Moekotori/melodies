# 多 TB 曲库扫描

目标是多个 TB、数十万至百万级文件；容量、文件数与单文件大小分别验证。容量本身不决定托管内存预算。实际速度取决于磁盘寻道、目录布局、文件格式及数据库所在介质。

## 本轮实施计划

1. CUE 定义流式枚举；去掉目录总虚拟曲目上限，抑制整曲的集合超出小内存预算后转为临时磁盘索引。单份损坏定义的解析上限继续保留。
2. 普通大目录只为目标扩展名创建路径/文件快照；不驻留文件夹音频列表。
3. osu 持久缓存低频清理，避免每 128 个谱面重扫几十万条缓存。
4. 消除首次入库时专辑播放历史的重复整组聚合；用户标签/隐藏状态和 CUE 音源协调 SQL 每批准备并复用，避免每首歌重新编译触发器。保留索引与同一事务中的派生事实。
5. 短测覆盖 >4 GiB 文件、数 TB 稀疏元数据夹具、超过 4096 个 CUE 音源、真实 SQLite 大批量写入、取消和重新打开后的增量恢复；所有验证累计不超过 120 秒。

## 调度、内存和正确性

- 默认两个 metadata worker，最多四个；发现队列两个批次、结果队列一个批次，单批最多 256。所有队列背压，UI 只接收节流进度与分页。
- 长整型保存文件长度、时间和总计数；扫描不计算完整音频哈希，不复制音频正文、封面与大标签块。
- CUE/FLAC 和原生解析仍限制单输入和回复长度；巨大或损坏标签报局部错误，不靠无限分配实现兼容。
- 每批独立事务，批次回执与曲目同时持久化；中断重开将旧任务标为 Interrupted。重新扫描重新枚举目录，复用已提交且属性/解析版本/依赖一致的事实。它是增量恢复，不是恢复操作系统目录枚举游标。
- 只有完整覆盖、无局部错误、正常完成的扫描才能标记缺失；取消、访问失败和断盘不能把未遍历的歌曲误标为消失。
- osu pack 保留单目录 4096 谱面、256 独立音源的解析保护；总曲库没有对应上限。特殊单目录超大 pack 尚需单独扩展，不能算作已支持任意布局。
- 临时抑制索引只保存当前目录的路径键，结束/取消释放；SQLite 曲库只有既有 writer owner。临时磁盘不足作为扫描失败处理，禁止悄悄漏掉去重。

## 验证证据

Windows Release，2026-10-02。本轮构建、失败修正与定向验证累计约 118 秒，未跑长测或完整打包。日志位于 `misc/large-library-validation/`。

| 检查 | 实测与含义 |
| --- | --- |
| 4 TiB 逻辑容量 | 512 个 Windows 稀疏 FLAC metadata 夹具，每个 8 GiB；真实发现/metadata/SQLite 路径通过，长度未截断。首次约 1346 ms（含初始化），复扫约 38 ms |
| 巨大 CUE 目录 | 4100 个定义和音源，流式展开 8200 首；无整曲重复，落盘集合正常释放，提前 Dispose 也释放。全枚举和一次提前退出合计约 16.94 s；这项检查验证发现，不是 8200 首完整入库测速 |
| 中断与覆盖 | 批次回执重试不重复写；重开旧 Running → Interrupted，128 首复用 + 128 首新增；取消不误标缺失，完整重扫准确标记 1 个已删除文件 |
| 缓存与升级 | 从 v17 升至 v18，备份存在；已有专辑播放历史未重复累计。预置 262272 条缓存，清理到 262144；反复更新近期项不误驱逐额外条目 |
| 最终 SQL 优化 | 5000 行真实 SQLite 入库约 2323 ms；写入期间分页查询最大 7.3 ms，后续第一页查询 P95 2.5 ms；完整分页遍历、分页索引检查通过 |
| 旧规则回归 | 最终实现的 CUE/osu 17 项检查通过，包含物理整曲恢复、虚拟来源与原生解析 |

5 万行探针在最后的 SQL 准备语句优化**之前**触发 45 秒预算，只提交 26368 行，不能算通过。最终修复仅重跑上述 5000 行探针；5 万行最终吞吐、百万级实库和真实多 TB HDD 尚未确认。5000 行探针末尾进程 private bytes 约 101.2 MiB，是后端瞬时读数，不包含 UI、完整原生进程组或长期峰值。

稀疏文件只验证 64 位长度和 metadata 路径，不是可播放音频，也不代表读取过真实数 TB 音频或 HDD 冷缓存速度。百万级实库、网络盘、三平台及长期运行仍需独立验收。当前仍保留 4096 字符路径、64 层目录深度与单份定义/标签保护。

## 文件与迁移

- Files/FolderSourceSet.cs 管理当前目录的内存/落盘抑制索引；LegacyFolderDiscovery 与 SelectedFileDiscovery 共用同一生命周期。
- Library/SourceCacheQueries.cs 在初次写入及每累计 4096 条缓存写入后维护；正常运行最多临时多 4095 行，不保留整库内存缓存。
- Library/LargeLibrarySchema.cs 只替换专辑插入触发器，schema 18 保持既有专辑/历史事实，已有库先做 SQLite 一致性备份。
- Library/VirtualAudioReconciliation.cs 与扫描批次中的用户状态语句均在唯一 writer 事务内复用；不添加第二个曲库写入 owner。
- 临时索引正常结束/取消删除；进程崩溃可留下一份 OS 临时目录中的 scratch 文件，后续不依赖其内容。
- 回滚 schema 18 应使用对应备份与兼容代码，不手动降低 user_version，也不对旧 ECHO 生产库执行此迁移。
