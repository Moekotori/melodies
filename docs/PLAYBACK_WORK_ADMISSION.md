# 播放压力下的后台准入与诊断

日期：2026-10-02。仅修改新 C# 工作区；没有重编或改写 C++ 音频回调，也没有打开旧 ECHO 生产库。

## 数据来源和真实性

`PlaybackPerformance` 属于唯一播放会话 owner 发布的状态。`audio.position` 的 operationId 与 transport epoch 检查通过后，才接受 bufferedFrames、inputEnded 及 processing 数据。旧曲目、seek 前或旧宿主的样本不能更新当前诊断。

确认 PCM 格式与输出采样率时才把帧数换算为缓冲毫秒。非 PCM 或格式/采样率未知时保留原始帧数，时间显示未知。沿用已有 stdout 汇总中的 underrunCallbacks / underrunFrames；它们是宿主范围计数，不假装是当前曲目的欠载次数。计数下降或 epoch 变化重新建立比较基线。

SRC/SDM 单阶段倍率使用原生报告的输入帧数、源采样率与处理耗时计算。它不代表完整 DSP 引擎、解码或设备回调的倍率。完整 DSP 倍率与回调长尾目前显示未知。缺失、null、错误类型或非有限数据不变成零，也不阻塞播放命令 lane。宿主诊断使用一个可合并槽，通道满时允许丢旧样本，不能将诊断拥塞变成播放故障。

## 准入规则

`PlaybackRuntime.BackgroundWork` 是本机播放共享的 `IBackgroundWorkAdmission`。它通过分类订阅读取最新状态，不访问 UI、设备或 SQLite，不新建全局任务队列。

| 状态 | 新 metadata 工作 | 新扫描提交 | 可见封面缺失 |
| --- | --- | --- | --- |
| 无活跃播放 | 最多 4，扫描仍遵循请求的 worker 数 | 沿用请求，最多 256 条 | 沿用一个封面 worker |
| 健康且稳定播放 | 最多 2 | 最多 256 条 | 普通路径 |
| 准备播放、遥测不足/过期、缓冲偏低 | 最多 1 | 最多 32 条 | 普通路径 |
| 确认播放压力保护 | 暂停新准入 | 等待后再提交 | 缓存命中立即返回，缺失最多增加 100 ms 让路 |

初始保护候选：确认 PCM 缓冲低于 30 ms 且持续至少 100 ms，或已过启动宽限后观察到新的宿主欠载。只在有效播放 operation、近期样本和非 EOF drain 情况下触发。已有响度、解码或设备事实不由 C# 推算。健康恢复有最小驻留和连续稳定窗口，先回到单 worker，再恢复两 worker；新播放/seek 重新建立基线。

buffer 样本超过 2 秒后过期；阶段样本超过 2.5 秒后不再用于判断。未知数据只限制并发，不会永久停扫。因播放压力等待的请求每 250 ms 检查一次过期和取消；没有等待者时不保留空闲轮询计时器。

metadata 最多 4 个活跃租约，阻塞请求最多 32 个，等待票据保证 metadata 准入顺序，取消移除票据，租约重复释放安全。现有有界发现/结果 Channel、payload 限制、图片像素预算与数据库唯一 writer 保持有效。

## 实际调用链

- 桌面扫描将 discovery MoveNext、批量已知项检查、必要 metadata 读取和每次提交接入准入。未变化项仍复用原结果。
- 提交批次在降载后安全切成较小子批，使用顺序递增回执；已经发出的写入等待确认，不因压力取消或重放。
- 可见封面的缓存命中绕过调度；后台 worker 的实际读取/解码继续有界。播放控制、交互查询、用户写入和原生下一曲准备不经过这个后台 gate。
- 沿用 DesktopLibrary 关闭取消，因保护等待的扫描也能安全退出。扫描显示 waiting_playback 的原因状态，不假装已经完成。

## 查看诊断

打开底栏信号路径的诊断展开区，可以查看 PCM 缓冲、宿主欠载、单阶段倍率、后台准入等级、原因及 metadata 并发。界面低频合并更新；面板打开时重新检查样本时间，隐藏主窗后的连续进度/性能展示停止。信号路径面板自己的计时器随可见生命周期释放。

独立 `Echo.Player` 提供 `perf` 命令。普通扫描 CLI 没有播放会话时沿用原路径，未强制加载音频宿主。

## 本轮短验证

`tests/Echo.Playback.Smoke -- --admission-only` 覆盖启动宽限、EOF drain、欠载、恢复滞回、缺失/过期/旧 operation、单阶段倍率、非 PCM 缓冲单位、错误类型诊断、取消、租约释放与原有分类订阅。

扫描链路使用 80 个小型生成文件、模拟必要 metadata reader 和真实独立 SQLite，确认保护中的取消不写入或做 missing 清理，过期恢复后的四 worker 请求最多同时一个 metadata 读取，最终提交 80 条。这是管线行为验证，不是实际磁盘吞吐或 p95 性能结论。

真实 Windows Native Host 的静音播放与双控制端 smoke 通过，实际读到缓冲 96,000 帧、宿主累计欠载 0。该结果不能外推为长时间无欠载、HDD/NAS 或高负载 DSP 验收。UI 重跑曾被并行队列、主题、歌曲、广播和弹层样式编译错误阻断，最后状态以 `misc/playback-pressure-validation/` 的日志为准。

最终核心检查与独立播放器构建通过，播放器构建为 0 警告、0 错误。整轮构建/检查/失败重跑累计约 60 秒。最新展开诊断区预览重跑在并行 `Sidebar.axaml.cs` 的 `Point.Length` 编译错误处停止，因此没有将新截图或最终完整桌面验收标为通过。

## 范围与回滚

这不是全局 CPU/内存调度器。尚未增加总 CPU 采样、原生完整 DSP/回调耗时、网络元数据排程、重音频分析、跨 Zone 资源分配或长期负载验收。阈值属于首版候选，需按真实播放压力场景校准。

回滚移除桌面扫描/封面注入与 runtime 准入 owner，即回到原有固定 worker 和有界队列。曲库 schema、生产库、音频输出模式与 C++ 数据面没有因此改变。
