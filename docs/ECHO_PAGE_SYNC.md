## 检查方法

`tools/Echo.PagePreview` 使用原生 Avalonia Headless 渲染真实视图，独立 SQLite 预览库和内存 RSS 传输夹具，音频输出显式不可用。支持浅色、深色和 1000 像素窄窗口，覆盖导航入口、详情、设置分类和连接子页。输出保存在 Git 忽略的 `artifacts/`。

本次已通过：`HEAD` 加本次页面改动的隔离构建（零错误），20 个导航入口、12 个设置分类、5 个连接工作区、3 类详情页及播客状态切换，共 125 张原生截图。截图位于 `artifacts/page-sync/verified/`。本次页面 diff 的空白检查通过；未测试真实音频输出。

前一轮共享工作区曾受并行 DSP 修改阻挡；本轮主页／底栏深化已通过当前共享源码的桌面依赖构建，不包含整套解决方案及真实音频设备验收。

### 主页与底栏深化

- 主页将封面与当前歌曲、本周聆听、统计入口、最近活动和艺术家排行重新编排；窄窗口把聆听统计放到主内容之后。推荐专辑改为有上限的响应式列表，保留原有查询、封面缓存及释放路径。
- 主页主按钮根据确认后的播放状态显示播放／暂停，并将操作发送给现有会话。没有新增播放 owner 或控制端状态猜测。
- 底栏按 ECHO 原版布局对齐：保持原来的封面尺寸、控制顺序、透明播放键、进度条和弹层入口。本轮尝试的圆形强调播放键、等宽分区、收藏移位与设备／音量常驻展示已撤回。
- 使用 `tools/Echo.PagePreview --home-player` 检查空闲、播放、暂停、真实预览库中的长标题、900／1000／1440／1920 像素、浅深色、125% 缩放与英文；原生指针检查主页暂停、底栏暂停、seek 和音量弹层。音频确认使用协议夹具，没有打开真实设备。

运行示例：

```powershell
dotnet run --project tools/Echo.PagePreview -- artifacts/pages
```

截图检查与聚焦构建不替代生产 Core、真实音频设备、远程配对、Steam 创意工坊或跨机器一起听歌的验收。并行修改导致当前工作区暂时不可构建时，单独记录当前工作区失败与隔离基线验证，不将二者混为一次完整构建通过。
