# 设置完整可用实施计划

目标：设置中的每个入口均有真实消费者、可确认的结果、持久化及失败恢复；不以取消禁用或只保存开关作为完成。旧 ECHO 只读，新应用数据库和配置独立。

现状证据：`SettingsViewModel.CreateRow` 仍有可用 ID 白名单，多数目录项没有命令消费者。窗口、语言、部分歌词和音频设置已有 owner。扫描/SQLite、播放会话和媒体控制已有模块，需要通过端口接入。

步骤：

1. 建立扩展设置状态、消费者注册和逐项可用性清单，替换静态白名单。
2. 接通新手引导、托盘、登录启动、窗口/无障碍及快捷键录制与注册。
3. 接通主题模式、预设/自定义、背景/字体/封面以及可视化偏好。
4. 接通输出/播放偏好、资源与扫描策略；保留唯一播放会话与数据库 owner。
5. 接通曲库文件夹、检查、隐藏/重复、资料重读、封面与 BPM，所有写入经现有协调者。
6. 接通本地设置/数据导入导出、一致性备份、WebDAV及安全恢复；破坏性动作先呈现明确确认。
7. 接通媒体/任务栏、Discord、OBS、Last.fm、ListenBrainz及设备联动；凭据由用户配置，不复制旧账号密钥。
8. 接通 Steam 实际协议、成就、统计、云同步与排行榜；客户端/许可条件如实显示。
9. 接通诊断、帮助和维护入口；把已内建或框架差异项作明确适配，不能声称不存在的后端已启用。
10. 逐模块短检查，最后用可用性清单与实际用户路径确认，不运行长全量测试。

文件边界：功能设置模块管本地展示和命令入口；平台、文件/数据库、网络和 native 适配保持分开。配置不得保存未经确认的有效状态，凭据另由保护存储持有。

资源与回滚：所有背景服务有停止和释放入口；HTTP/IPC/任务/缓存有数量与字节上限；页面离开取消迟到结果。新配置采用有界、原子写入，导入先备份。停止新应用可继续旧 ECHO，不覆盖生产库。

验证：单条60秒，整轮120秒；只检查本轮模块和必要真实边界。编译、协议、连接、账号和设备验收分别记录。
