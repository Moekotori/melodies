# 歌词样式原版对齐

日期：2026-10-02。验收依据为旧版实际控件与样式，不以样式 ID 数量或原生截图数量代替保真度。

上一轮只保留了入口和大致意象，统一的字号 / 行距、错误的唱片图案、折光几何线、映幕遮幅比例、固定余晖颜色和余音词抬升都与源实现存在显著差别。本轮删除这些替代实现，按下表的具体源码规则修订。

| 样式 | 修订依据 | 本轮变化 |
| --- | --- | --- |

| 浮光 | `lyrics-luminous.css` | 仅前一句 / 当前 / 后一句；上下文不排副文本；独立密度字号、640 / 760 字重、光轨与副文本位置 |
| 余音 | `afterglowGlyphs.css`、`afterglowGlyphTiming.ts`、`afterglowGlyphMotion.ts` | 居中单句、6vw / 2倍字号、词内字素分时、原种子几何、弹簧响应、缩放 / 旋转 / 入场与释放透明度；最多 192 字素 |

背景恢复实际封面模糊。封面取色只在原封面工作器执行，并且只为舞台的较大分辨率租约采样；普通 320 像素缩略图的读取 / 解码路径没有新增采样。缓存 owner 和预算沿用既有封面服务。字素、词栏与可见行均缓存排版，不在每帧拼接文本，不增加每词 / 每字控件或定时器。

## 验证及剩余差异

定向构建和实际原生控件短测已通过；输出在 `misc/lyrics-fidelity/native/`。它们能确认控件运行与状态 / 生命周期，但不能证明与旧版视觉完全相同。

在新工作区建立了只读取旧 React 控件 / CSS 的隔离网页，使用相同歌曲、封面、6000ms 时间点；不启动旧 Electron、不使用 preload、不访问旧生产库。Vite 缓存也放在新工作区。内置浏览器的本地导航被阻止，Chrome 连接不可用；Playwright 截图许可尚在等待用户回复。因此本轮没有取得可接受的旧版对照截图，尚未完成同视口像素 / 动态视觉验收。

后续已用原版脚本、规划器和场景实现替换 JIZURA 方向演示，补齐第 23 个音游主题并接入真实独立界面；原引擎 23 外观绘制及原生代表主题短测通过。代码、原生像素桥与验证边界见 [JIZURA_NATIVE_ENGINE.md](JIZURA_NATIVE_ENGINE.md)。

普通样式的字素光环 / 入场模糊、切影纵排边缘歌词、完整透视、段落转场与封面取样的采样尺寸差异仍需真实对照收口。没有取得旧版截图和完整动态对照，不能宣称全部样式与旧版视觉完全相同。

## 2026-10-19：同步当前 Electron 阅读样式

参考 `/Users/moekotori/echo` 的 `a44881fcc`。参考仓库保持只读；改动属于 Control 的歌词展示层，不改变 Core 队列、解析或原生播放事实。

- 简约恢复居中、Outfit 字体链、带封面的曲目信息、开头数行自然起点；按 Unicode 字符和折叠空白计算密度，补齐双副文本及长句行高。
- 按 `lyricsReading.css` 同步前后行透明度与模糊层次；保留用户透明度为零的语义。上下边缘使用渐隐蒙版，不再整行突然裁去。
- 扫光使用 `lyrics.css` 的四档柔化边缘；切行改为测量行框，普通 / 快速 / 瞬时显示窗口分别使用 360 / 60 / 0 ms。
- 新增原版 `curtain`（垂帘）、`kineticChars`（跃动）的独立绘制实现；竖排复用已有中西文方向处理，跃动复用同一有限帧驱动，未建立逐字控件或独立计时器。竖排只保留最多七行，每个文本最多 192 个字素。
- 同步封面阅读样式的竖屏封面、标题和歌词区域；画境字号与副文本重新读取原版用户字号比例。
- 默认阅读、垂帘、跃动补回原版封面氛围渐变层；纹理仍由现有有界封面管线生成。

dotnet run --no-build -c Release --project tests/Echo.Lyrics.Smoke -- misc/lyrics-sync/final --styles-only

已完成主工作区 Release 构建、15 个原生样式和 5 个竖屏布局截图、暗色主题检查，以及跃动的隐藏 / 减少动效停止帧驱动检查。原生截图是实际 Avalonia 控件渲染，测试播放宿主提供固定位置；不代表真实音频设备验收。竖屏请求宽 700，实际窗口受最小宽度限制为 800，截图为 800 × 960。

用新工作区内隔离 Vite 预览直接加载原版 `LyricsView` 与 CSS，并在内置浏览器观察其行框、字体、透明度和自然滚动起点；缓存也只写入本仓库。该预览用于核对阅读规则，未完整装配 Electron 的所有页面背景、设置和场景。

**尚不能称为全量一模一样。** 当前 Electron 的独立 Blossom / Cassette 场景尚未迁入。垂帘长句自动折列、完整三维折光、跃动入场模糊、通用逐字高亮的其他可选效果、各主题的完整配色联动，以及所有样式逐帧像素对照仍未完成。不能用此次原生截图通过代替这些验收。


## 2026-10-19：补齐独立原版场景与排版细节

在 `codex/lyrics-fidelity` 隔离工作区继续完成，来源仍为只读 Electron `a44881fcc`。样式目录现为 17 项：包含原版 Blossom、磁带、垂帘、跃动，以及已有 Afterglow 的 23 个外观。

- Blossom 直接运行原版规划器、17 种镜头排版、背景、转场、字素运动和交互命中代码。Canvas 宿主只提供绘图与文字测量；最终画面通过不可变 Skia picture 交给 Control。
- 磁带复用原版时间轴、昼夜场景、粒子、逐字运动、水波和 VHS 着色器，以及现有 30 张素材。GLSL 按明确的坐标 / uniform 对应转为 SkSL；没有嵌入浏览器。实际封面通过已有展示租约一次快照，工作器裁为 256 像素，进入磁带轮。来源记录见 `LYRICS_CASSETTE_SOURCE.md`。
- macOS 使用系统 JavaScriptCore 的公开 C API，其他平台使用已有 Jint 解释器。两者都只暴露有类型检查的绘图操作与受限基本值，没有 CLR / 音频 / 网络 / 文件访问。Native AOT 控制台已发布并实际绘出磁带三帧；未据此宣称其他平台的设备验收完成。
- 场景只有一个串行工作器和一个可替换待绘请求；点击另有单槽保留，不会因帧合并丢失。窗口隐藏、离开样式和释放视图会停止驱动、释放画面并清理引擎；播放仍由 Core / 原生音频宿主持有。
- 纹理最多 48 张 / 64 MiB；Canvas 像素池最多 16M 像素；输入最多 512 行 / 32768 主文本字符，并限制 JSON 与图像大小。字体缓存最多 64 种样式、每种 12 个解析字体。保留逻辑视口与源引擎的后台缓冲比例：磁带最多 1920×1080，Blossom 沿用 5M 像素目标和原版 DPR 下限，并受总像素池约束；避免大屏下把 36px 歌词错误放大为 72px。可见 30 fps、失焦 15 fps。动态位置来自原生确认时钟，点击 seek 使用原有 offset 换算。
- 垂帘补齐长句折列、副文本列宽、原竖排行距 / 字距和组居中；折光改为完整 4×4 变换投影，不再用余弦压扁代替透视；跃动补齐 6px 入场模糊、光点与 520ms 下划线过渡。
- Canvas 修正 CSS 八位颜色的 RGBA 顺序、真实字体度量、overlay、叠加的 contrast / brightness 过滤器、save / restore 的阴影状态。离屏背景保留原版的降采样位图，避免跨帧 picture 反馈产生递归图与资源增长。

聚焦验证：Release 构建；17 个实际 Avalonia 样式、5 个竖屏布局、3840×2160 磁带逻辑视口、暗色主题、场景减少动效 / 隐藏 / 恢复 / 离开释放；macOS arm64 Native AOT 场景绘制。原生设备播放未包含在这次纯展示改动的验收中。

同视口对照使用原版引擎与同一 fixture：1440×900、6000ms、关闭空间动效、磁带 36 / 18px。并排图见 `misc/lyrics-fidelity/final/compare-blossom.png` 与 `compare-cassette.png`。已修正比较发现的磁带字号和逐字光晕偏差。保留的细微差异包括系统字体回退、Canvas / Skia 抗锯齿、后期着色器在不同后端的采样；这些截图不构成所有动态帧逐像素相同的证明。最新对照记录见仓库根目录 `design-qa.md`。
